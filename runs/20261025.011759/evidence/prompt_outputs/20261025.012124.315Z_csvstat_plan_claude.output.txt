# ARCHITECTURE: CsvStat

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Module layout, boundaries, and technical decisions for the csvstat command-line CSV column profiler. |
| Depends On  | None |
| Provides    | go.mod, cmd/csvstat, internal/cli.Run |
| Consumes    | None |

## Questions

- None.

## Purpose

`csvstat` is a single-binary Go command-line tool. It reads one CSV file, infers a type for each column, and writes either a profile table or a frequency list to standard output as CSV. Diagnostics go to standard error. Exit codes are 0 (success), 1 (operational failure), 2 (usage error), and 3 (rejected input).

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`, which remains the decision of record.

| Technology | Where it applies |
|---|---|
| Go 1.22 or newer, standard library only | Every package; no third-party modules and no `require` line in `go.mod` |
| go test and go vet | The project suite behind `bin/test.sh` |
| CSV (RFC 4180, `encoding/csv`) | Reading input and writing output |
| POSIX sh | `bin/test.sh` and the supplied grader `sources/run.sh` |

There is no database and no persistent state, so there is no `DATABASE.md`.

## Layout

```text
go.mod                    module declaration, Go 1.22 or newer, no dependencies
cmd/csvstat/main.go       process startup; the only caller of os.Exit
internal/cli/             Run(args []string, stdout, stderr io.Writer) int
internal/csvio/           reading, trimming, and rejecting CSV input
internal/profile/         null rule, type inference, counts, statistics, frequencies
internal/output/          profile and frequency CSV writers
bin/test.sh               POSIX test runner
```

## Modules and Boundaries

| Module | Owns | Allowed to use |
|---|---|---|
| `cmd/csvstat` | Wiring `os.Args[1:]`, `os.Stdout`, `os.Stderr` into `cli.Run`; calling `os.Exit` | `internal/cli` |
| `internal/cli` | Argument parsing with a local `flag.FlagSet` (`flag.ContinueOnError`), exit-code mapping, diagnostics, orchestration | `csvio`, `profile`, `output` |
| `internal/csvio` | Opening and reading the file, trimming, structural rejection | `os`, `encoding/csv` |
| `internal/profile` | Null classification, typing, counts, exact arithmetic with `math/big`, frequencies | `math/big`, `time`, `sort` |
| `internal/output` | CSV writing through `encoding/csv` with `\n` line endings | `encoding/csv` |

Persistence, configuration, file-store, and external-service boundaries: none. The only file access is reading the one input path named on the command line, owned by `internal/csvio`.

## Technical Decisions

- Only `main` calls `os.Exit`; `Run` returns the exit code so tests drive it with `bytes.Buffer` writers.
- Nothing is written to standard output until the whole input has been read and validated, so a failing command writes nothing to standard output.
- Sums, means, and medians are exact (`big.Rat`) and rounded once, half away from zero, when written.
- Application code never reads `sources/run.sh` or any supplied data file and embeds no answer.
- Invalid UTF-8 is accepted; blank lines are skipped by `encoding/csv`.

=== AC build-standard-library-only ===
Intent: Every non-test Go source file imports only standard library packages or packages of this module.

import os
import re

with open("go.mod", encoding="utf-8") as handle:
    gomod = handle.read()
module = re.search(r"^module\s+(\S+)", gomod, re.MULTILINE).group(1)

import_line = re.compile(r'^\s*(?:[A-Za-z_.]+\s+)?"([^"]+)"\s*$')
checked = 0
for root, dirs, files in os.walk("."):
    dirs[:] = [d for d in dirs if d not in ("sources", ".git", "vendor")]
    for name in files:
        if not name.endswith(".go") or name.endswith("_test.go"):
            continue
        in_block = False
        with open(os.path.join(root, name), encoding="utf-8") as handle:
            for line in handle:
                stripped = line.strip()
                if stripped.startswith("import ("):
                    in_block = True
                    continue
                if in_block and stripped == ")":
                    in_block = False
                    continue
                single = re.match(r'^import\s+(?:[A-Za-z_.]+\s+)?"([^"]+)"', stripped)
                path = None
                if single:
                    path = single.group(1)
                elif in_block:
                    found = import_line.match(line)
                    if found:
                        path = found.group(1)
                if path is None:
                    continue
                checked += 1
                first = path.split("/")[0]
                assert "." not in first or path.startswith(module), (name, path)
assert checked > 0
=== END AC build-standard-library-only ===

# FEATURE: CSV Reader

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Read a CSV file with encoding/csv, taking the first record as the header and trimming every header name and value. |
| Depends On  | ARCHITECTURE.md |
| Provides    | internal/csvio.Read |
| Consumes    | None |

## Questions

- None.

## Purpose

`internal/csvio` reads the file as RFC 4180 CSV with `encoding/csv`. The first record is the header. Every header name and every value is trimmed of leading and trailing spaces before any other rule applies. Structural rejection (empty file, bad header, ragged record) belongs to the InputRejection feature; this feature supplies the parsed, trimmed records and their line numbers.

## Interface

`csvio.Read(path string) (*Table, error)` where `Table` carries:

- `Header []string`: trimmed header names.
- `Rows [][]string`: trimmed data records in file order.
- `Lines []int`: the 1-based starting line of each data record (from `csv.Reader.FieldPos`), kept for diagnostics.

The reader sets `FieldsPerRecord = -1` so that a field-count mismatch is detected by the application and not by `encoding/csv`, which lets the caller name the offending line. `LazyQuotes` stays false. A quoted field containing a comma, a quote, or a newline is returned as one field.

## Behavior

- Trim spaces from header names and values, for example a value `  Globex  ` becomes `Globex`.
- A quoted field that contains a comma stays one field.
- Blank lines are skipped by `encoding/csv`.
- Invalid UTF-8 bytes are read and not rejected.
- Failure to open or read the file is returned as an error distinguishable from a CSV syntax error, so the caller can map it to exit 1 or exit 3.

## Required Project Tests

The build writes these tests in `internal/csvio` using files the tests create. Acceptance runs them by exact name.

- `TestReadTrimsHeaderAndValues`: padded header names and padded values come back trimmed.
- `TestReadKeepsQuotedCommaInOneField`: a quoted field containing a comma is one field.
- `TestReadReturnsRecordLines`: `Lines` has one entry per data record and reflects the file line.
- `TestReadAcceptsInvalidUTF8`: a file with a byte that is not valid UTF-8 is read without error.
- `TestReadMissingFileIsOpenError`: a missing path returns an error that is not a CSV parse error.

# FEATURE: Input Rejection

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Reject an empty, malformed, or ragged CSV file with exit 3, nothing on standard output, and one diagnostic line on standard error. |
| Depends On  | FEATURE-CsvReader.md, ARCHITECTURE.md |
| Provides    | exit code 3 for rejected input |
| Consumes    | internal/csvio.Read |

## Questions

- None.

## Purpose

After reading the file, the application rejects it when any of these holds:

- the file is empty (no header record);
- a header name is empty after trimming;
- a header name is repeated;
- any data record has a different number of fields from the header;
- `encoding/csv` reports a syntax error (a `csv.ParseError`), such as a bare quote.

A rejected file exits 3, writes nothing to standard output, and writes one line to standard error naming the file and, for a record, its line number. Standard error text is never compared.

## Behavior

- Validation completes before anything is written to standard output.
- The ragged record is identified by the line number the reader recorded for it.
- A file with a header and no data records is valid and is not rejected.
- An open or read failure is not a rejection; it is exit 1 (FEATURE-ReadFailure.md).

# FEATURE: Read Failure

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Report a file that cannot be opened or read, including a directory path, with exit 1 and nothing on standard output. |
| Depends On  | FEATURE-CsvReader.md, ARCHITECTURE.md |
| Provides    | exit code 1 for operational failure |
| Consumes    | internal/csvio.Read |

## Questions

- None.

## Purpose

When the file path cannot be opened or read, the application exits 1, writes nothing to standard output, and writes one diagnostic line to standard error naming the path. This covers a missing file, a permission failure, and a path that names a directory. The application must not panic; a Go panic exits 2, which would be misreported as a usage error.

## Behavior

- An open failure from `os.Open` maps to exit 1.
- A read failure after opening, such as reading a directory, maps to exit 1.
- A valid path with a malformed argument list is a usage error (exit 2), decided before the file is touched.
- A CSV syntax or structure problem is a rejection (exit 3), not exit 1.
