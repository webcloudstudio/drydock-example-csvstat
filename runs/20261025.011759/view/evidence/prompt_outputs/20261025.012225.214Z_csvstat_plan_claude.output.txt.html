# FEATURE: Null Values

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Classifies empty, NA, N/A, and NULL values as null after trimming. |
| Depends On  | FEATURE-CsvReader.md |
| Provides    | internal/profile.IsNull |
| Consumes    | internal/csvio.Read |

## Questions

- None.

## Purpose

Every statistic, type, and frequency rule applies only to non-null values. This feature supplies the single predicate that decides whether a value is null, so counts, typing, statistics, and frequency lists agree.

## Behavior

- Package `internal/profile` exports `IsNull(value string) bool`.
- The value is trimmed of leading and trailing spaces before the test, so the predicate gives the same answer for a padded value and its trimmed form.
- A value is null when the trimmed value is empty, or equals `NA`, `N/A`, or `NULL` ignoring case (`na`, `n/a`, `Null`, `null` are null).
- Every other value is non-null, including near misses such as `NAN`, `N/B`, `NULLS`, `none`, and `0`.
- The predicate is pure: no I/O, no package state.

## Required project tests

The builder writes these tests in `internal/profile` beside the code, with exactly these names:

- `TestIsNullEmpty`: the empty string and whitespace-only strings are null.
- `TestIsNullSpellings`: `NA`, `N/A`, `NULL` in upper, lower, and mixed case are null, including when padded with spaces.
- `TestIsNullNonNull`: near misses and ordinary values are not null.

# FEATURE: Arguments

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Parses the csvstat command line and rejects malformed usage with exit 2. |
| Depends On  | FEATURE-Build.md |
| Provides    | --column, --freq, --top, exit code 2 |
| Consumes    | internal/cli.Run |

## Questions

- None.

## Purpose

The command forms are `csvstat [--column <name>] <file>` and `csvstat --freq <name> [--top <n>] <file>`. This feature parses them and turns every usage mistake into exit code 2 with nothing on standard output.

## Behavior

- `internal/cli.Run(args []string, stdout, stderr io.Writer) int` parses `args` with a local `flag.FlagSet` created with `flag.ContinueOnError`, its own output set to `io.Discard`.
- Options precede the file. Exactly one positional argument, the file, is required. Anything after the first positional argument counts as an extra argument.
- Recognized options: `--column <name>`, `--freq <name>`, `--top <n>`.
- Exit 2 with empty standard output for each of:
  - no file, or more than one file;
  - an unknown option;
  - an option given without its value;
  - `--column` together with `--freq`;
  - `--top` without `--freq`.
- On exit 2, write exactly one line to standard error naming both command forms. There is no `--help` option.
- A well-formed command line is accepted and handed to the later behavior; it never exits 2.
- A `--top` value that is not a positive integer is owned by the `--top` feature (FEATURE-FrequencyTop.md), not this one.

## Required project tests

The builder writes tests calling `cli.Run` with `bytes.Buffer` writers for every case above, asserting the exit code, empty standard output, and a single-line diagnostic.

# FEATURE: Type Numeric

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Infers the integer and number column types from a column's non-null values. |
| Depends On  | FEATURE-NullValues.md |
| Provides    | internal/profile.InferType |
| Consumes    | internal/profile.IsNull |

## Questions

- None.

## Purpose

A column's type is the first of `integer`, `number`, `date`, `boolean`, `text` that every non-null value satisfies, or `empty` when there is no non-null value. This feature creates the typing function and implements its first two rungs; later features add the remaining rungs to the same function.

## Behavior

- Package `internal/profile` exports `InferType(values []string) string`. Values are already trimmed; null values are skipped using `IsNull`.
- Returns `"integer"` when every non-null value matches `^-?[0-9]+$`.
- Returns `"number"` when every non-null value matches `^-?[0-9]+(\.[0-9]+)?$` and at least one value is not an integer.
- Integer text with leading zeros or a leading `-` and digits is still an integer; `+5`, `.5`, `5.`, `1e3`, `1,000`, and a bare `-` are not numeric.
- Typing considers only non-null values: a column of integers and nulls is `integer`.
- The ladder order is integer, number, date, boolean, text; a column that satisfies an earlier rung never takes a later one.
- Non-numeric columns fall through to later rungs, implemented by FEATURE-TypeDate.md and FEATURE-TypeOther.md. Until they exist, a non-numeric column returns `"text"`.

## Required project tests

The builder writes these tests in `internal/profile` with exactly these names:

- `TestInferTypeInteger`: integer columns, negative values, leading zeros, and integers mixed with nulls.
- `TestInferTypeNumber`: decimals, negative decimals, decimals mixed with integers, and decimals mixed with nulls.
- `TestInferTypeNotNumeric`: forms such as `+5`, `.5`, `5.`, `1e3`, `1,000`, and `-` are not integer or number.

# FEATURE: Type Date

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Infers the date column type with real calendar validation. |
| Depends On  | FEATURE-TypeNumeric.md |
| Provides    | date type |
| Consumes    | internal/profile.InferType |

## Questions

- None.

## Purpose

A column is a `date` column when every non-null value is a real calendar date written `YYYY-MM-DD`. A value such as `2025-02-30` has the right shape but is not a date, so it keeps its column out of this type.

## Behavior

- `InferType` returns `"date"` when the column is not integer or number and every non-null value matches `^[0-9]{4}-[0-9]{2}-[0-9]{2}$` and parses with `time.Parse("2006-01-02", value)` without error.
- The shape check is strict: the value must be exactly ten characters in that form; a single-digit month or day, a time suffix such as `2025-03-01T08:00`, or a slash separator is not a date.
- Calendar validity includes month length and leap years: `2024-02-29` is a date, `2025-02-29` and `2025-04-31` are not.
- A single invalid date among valid ones sends the column to the later rungs (boolean, text), so it becomes `text`.
- Null values are ignored.
- A column that is entirely integers or numbers keeps that earlier type.

## Required project tests

The builder writes these tests in `internal/profile` with exactly these names:

- `TestInferTypeDate`: valid dates, leap day, and dates mixed with nulls are typed date.
- `TestInferTypeInvalidDate`: impossible calendar dates, wrong shapes, and time suffixes make the column text.

# FEATURE: Type Other

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Infers the boolean, text, and empty column types. |
| Depends On  | FEATURE-TypeNumeric.md |
| Provides    | boolean, text, empty types |
| Consumes    | internal/profile.InferType |

## Questions

- None.

## Purpose

This feature completes the typing ladder: `boolean` for true/false columns, `text` as the catch-all, and `empty` for columns with no non-null value.

## Behavior

- `InferType` returns `"empty"` when no value in the column is non-null. This includes a column with no rows at all, a column of only empty strings, and a column of only `NA`, `N/A`, or `NULL` spellings.
- `InferType` returns `"boolean"` when the column is not integer, number, or date, and every non-null value equals `true` or `false` ignoring case (`TRUE`, `False`).
- `InferType` returns `"text"` for every other column, including a column mixing booleans with other words, or booleans with numbers.
- Null values are ignored for every rung; a column of booleans and nulls is `boolean`.
- `yes`, `no`, `1`, `0`, `t`, `f` are not booleans.
- `empty` takes precedence over every other type because it is decided first, by the absence of non-null values.

## Required project tests

The builder writes these tests in `internal/profile` with exactly these names:

- `TestInferTypeBoolean`: mixed-case true/false columns, with and without nulls.
- `TestInferTypeText`: ordinary words, mixed booleans and words, padded and punctuated strings.
- `TestInferTypeEmpty`: no values, only empty strings, only null spellings.
