# FEATURE: Column Select

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Profile only the column named by --column and reject an absent name with exit 3. |
| Depends On  | FEATURE-ProfileOutput.md, FEATURE-Arguments.md, FEATURE-InputRejection.md |
| Provides    | --column behavior |
| Consumes    | profile table on standard output |

## Questions

- None.

## Purpose

`csvstat --column <name> <file>` writes the profile header followed by the single row for the named
column. The row is identical to the row the full profile writes for that column. A name that is not
in the header is a rejected input.

## Behavior

- Output is the header `column,type,rows,nulls,distinct,min,max,sum,mean,median` and exactly one
  row, for the named column, written with the same `encoding/csv` writer as the full profile.
- The name is compared to the trimmed header names as an exact string.
- A name absent from the header exits 3, writes nothing to standard output, and writes one
  diagnostic line naming the file to standard error.
- The whole file is still read and validated first, so a ragged file exits 3 regardless of the
  column named.

## Programmatic Acceptance

# FEATURE: Frequency

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | List the most frequent non-null values of one column ordered by count descending then value ascending. |
| Depends On  | FEATURE-NullValues.md, FEATURE-ProfileOutput.md, FEATURE-Arguments.md, FEATURE-InputRejection.md |
| Provides    | --freq behavior |
| Consumes    | internal/profile.IsNull |

## Questions

- None.

## Purpose

`csvstat --freq <name> <file>` replaces the profile with a frequency listing of one column.

## Behavior

- Output header is `value,count`, written with the `encoding/csv` writer and `\n` line endings.
- One row per distinct non-null value of the named column, values compared as exact trimmed
  strings.
- Rows are ordered by count descending, then by value ascending by byte value.
- Null values (empty, `NA`, `N/A`, `NULL` ignoring case, after trimming) are not listed.
- A column with no non-null values writes only the header and exits 0.
- At most 5 rows are written when `--top` is not given. `--top` itself is specified in
  FEATURE-FrequencyTop.md.
- A name absent from the header exits 3 with nothing on standard output.

## Programmatic Acceptance

=== AC frequency-ordering ===
Intent: Frequencies list non-null trimmed values by count descending then byte-ordered value, matching counts computed from the input file.
Requires: executable=go; scope=test

import csv
import io
from collections import Counter
from drydock_go import cli_runner

data = "sources/orders.csv"
column = "customer"
with open(data, newline="") as handle:
    records = list(csv.reader(handle))
index = [name.strip() for name in records[0]].index(column)
nulls = {"", "na", "n/a", "null"}
values = [row[index].strip() for row in records[1:]]
counts = Counter(v for v in values if v.lower() not in nulls)
ordered = sorted(counts.items(), key=lambda item: (-item[1], item[0].encode()))
expected = [[value, str(count)] for value, count in ordered][:5]

code, out, err = cli_runner("--freq", column, data)
assert code == 0, (code, out, err)
rows = list(csv.reader(io.StringIO(out)))
assert rows[0] == ["value", "count"], rows[0]
assert rows[1:] == expected, (rows[1:], expected)
=== END AC frequency-ordering ===

# FEATURE: Frequency Top

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Limit frequency rows with --top and reject a non-positive or non-integer value with exit 2. |
| Depends On  | FEATURE-Frequency.md |
| Provides    | --top behavior |
| Consumes    | --freq behavior |

## Questions

- None.

## Purpose

`--top <n>` bounds the number of rows `--freq` writes.

## Behavior

- `--top n` writes at most `n` frequency rows; the default is 5.
- `n` must be a positive integer. Zero, a negative number, a non-numeric value, or a decimal exits
  2 with nothing on standard output.
- `--top` without `--freq` exits 2 with nothing on standard output.
- When `n` exceeds the number of distinct non-null values, all of them are listed.
- The limit applies after ordering, so the rows kept are the most frequent.

## Programmatic Acceptance

## Questions

- None.

## Purpose

`bin/test.sh` is the single command that gates every behavioral story. The project's own Go test
suite is written beside the code and covers each type, each statistic, null handling, rounding,
each output form, and each exit code, using files the tests write themselves.

## Behavior

- POSIX sh only; no bashisms. It changes to the application root (the directory above `bin/`) so it
  works from any current directory.
- It runs `go vet ./...` and then `go test ./...`, and exits zero only when both succeed. A failure
  of `go vet` stops the script with a non-zero status.
- Tests call `cli.Run(args, &stdout, &stderr)` with `bytes.Buffer` writers and write their fixture
  files under `t.TempDir()`. They never read `sources/run.sh`.
- The suite covers: each of the five types, min/max per type, sum/mean/median, half-away-from-zero
  rounding including negatives, null classification, quoting of fields with commas, frequency
  ordering and `--top`, and exit codes 1, 2, and 3.
