# ARCHITECTURE: CsvStat

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Module layout, package ownership, and boundaries of the csvstat command-line CSV column profiler. |
| Depends On  | None |
| Provides    | go.mod, cmd/csvstat, internal/cli.Run |
| Consumes    | None |

## Questions

- None.

## Purpose

CsvStat is a single-binary command-line profiler written in Go 1.22 or newer using only the
standard library. It reads one CSV file, infers each column's type, reports counts, extremes, and
for numeric columns the sum, mean, and median, and can list the most frequent values of one column.
There is no persistence and no network I/O.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`:

| Technology | Where it applies |
|---|---|
| Go 1.22 or newer | The whole application; standard library only, no third-party modules. |
| go test and go vet | The test runner behind `bin/test.sh`. |
| CSV (RFC 4180 via `encoding/csv`) | Input reading and output writing. |
| POSIX sh | `bin/test.sh` and the supplied grader `sources/run.sh`. |

## Module Layout

```text
go.mod                    # module path, go 1.22 or newer, no require lines
cmd/csvstat/main.go       # package main; calls internal/cli.Run and passes the code to os.Exit
internal/cli/             # argument parsing, usage text, dispatch, exit-code mapping
internal/csvio/           # file opening, CSV reading, trimming, validation
internal/profile/         # null rules, type inference, counts, statistics, frequencies
internal/decimal/         # exact arithmetic with math/big and two-decimal formatting
bin/test.sh               # POSIX sh: go vet ./... then go test ./...
```

`internal/cli.Run(args []string, stdout, stderr io.Writer) int` is the single entry point. Only
`cmd/csvstat/main.go` calls `os.Exit`. Behavior is tested with `bytes.Buffer`.

## Module Ownership

| Boundary | Owning package | Low-level APIs it may access |
|---|---|---|
| Command-line arguments, usage text, exit codes | `internal/cli` | `flag`, `io` |
| File access and CSV parsing | `internal/csvio` | `os`, `encoding/csv`, `strings` |
| Column semantics (null, type, counts, stats, frequency) | `internal/profile` | `time`, `sort`, `bytes` |
| Exact numbers and rounding | `internal/decimal` | `math/big` |
| Persistence, configuration files, external services | none | not applicable |

## Exit Codes

| Code | Meaning |
|---|---|
| 0 | Success. |
| 1 | The file cannot be opened or read. |
| 2 | Usage error. |
| 3 | Rejected input: empty file, empty or repeated header name, ragged record, CSV syntax error, or a column name absent from the header. |

A failing command writes nothing to standard output and one diagnostic line to standard error.
Output is buffered until validation completes.

## Constraints

- Application code never reads `sources/run.sh` or any supplied data file and never embeds a
  statistic, type, or value list.
- Sums, means, and medians are exact (`math/big`) and rounded once, half away from zero, at output.
- Input bytes are compared as bytes; a byte-order mark is not stripped.

# FEATURE: Command Line Parsing

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Accept the two csvstat command forms and the --help text, producing a typed request for dispatch. |
| Depends On  | ARCHITECTURE.md |
| Provides    | csvstat [--column <name>] <file>, csvstat --freq <name> [--top <n>] <file>, csvstat --help |
| Consumes    | internal/cli.Run |

## Questions

- None.

## Purpose

`internal/cli` parses arguments with a local `flag.FlagSet` created with `flag.ContinueOnError`,
whose output is directed to standard error. Options precede exactly one file.

| Option | Meaning |
|---|---|
| `--column <name>` | Profile only the named column. |
| `--freq <name>` | List the most frequent values of the named column. |
| `--top <n>` | With `--freq`, list at most n values; default 5. |
| `--help` | Write usage text to standard output and exit 0. |

## Behavior

1. Parsing yields a typed request: mode (profile or frequency), column name, frequency name, top
   count, and file path.
2. `--help` writes usage text naming both command forms and every option to standard output and
   returns 0, writing nothing to standard error.
3. Profile and frequency modes are dispatched through small interfaces held by `Run`, so later
   stories plug in without changing parsing.
4. Names given to `--column` and `--freq` are kept exactly as given; they are matched later,
   exactly and case-sensitively, against trimmed header names.
5. Usage-error exit mapping is owned by the usage-errors story; this story only has to produce the
   request for a well-formed command line.

## Required Go Tests

The build adds these tests in `internal/cli` (names are exact): `TestParseHelp`,
`TestParseColumnForm`, `TestParseFreqForm`.

# FEATURE: CSV Reading and Profile Output

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Read a well-formed CSV file and write the profile header and one row per column in file order. |
| Depends On  | FEATURE-CliParsing.md, ARCHITECTURE.md |
| Provides    | profile output header and rows |
| Consumes    | csvstat [--column <name>] <file> |

## Questions

- None.

## Purpose

`internal/csvio` opens the file and reads it with `encoding/csv` as RFC 4180 defines it; the first
record is the header. The profile mode writes CSV to standard output with `\n` line endings.

## Behavior

1. The reader sets `FieldsPerRecord = -1` so field-count validation is done by the application,
   which is owned by the rejection story.
2. Standard output starts with the header `column,type,rows,nulls,distinct,min,max,sum,mean,median`,
   then one row per column in file order. Each row has exactly ten fields; the first is the column
   name. The remaining fields are produced by the later counts, types, and statistics stories; this
   story establishes the row structure.
3. A quoted field containing a comma is read as one value. A field containing a comma, a double
   quote, or a newline is quoted on output by the `encoding/csv` writer.
4. A file with a header and no data records succeeds with one row per header column.
5. Bytes are compared as bytes: a byte-order mark is not stripped and the file is not rejected for
   invalid UTF-8.
6. Output is written to a buffer and copied to standard output only after reading succeeds.

## Programmatic Acceptance

=== AC csvread-header-and-columns ===

# FEATURE: Value Trimming

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Trim leading and trailing spaces from every header name and every value before any other rule applies. |
| Depends On  | FEATURE-CsvReading.md, ARCHITECTURE.md |
| Provides    | trimmed header names and values |
| Consumes    | profile output header and rows |

## Questions

- None.

## Purpose

Leading and trailing spaces are removed from every header name and every value before null, type,
distinct, and output rules apply. Trimming is done once, in `internal/csvio`, so every later rule
sees trimmed text.

## Behavior

1. Only the space character is trimmed (`strings.Trim(s, " ")`); tabs and other whitespace remain.
2. Header names are trimmed before the empty-name and repeated-name checks.
3. Values are trimmed before the null test, so a value of spaces only is empty and therefore null.
4. Column names written in the profile output are the trimmed names.

## Required Go Tests

The build adds these tests in `internal/csvio` (names are exact): `TestTrimHeaderNames`,
`TestTrimValues`.

# FEATURE: Reject Malformed Input

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Reject empty files, bad header names, ragged records, and CSV syntax errors with exit code 3 and nothing on standard output. |
| Depends On  | FEATURE-CsvReading.md, ARCHITECTURE.md |
| Provides    | exit code 3 for rejected input |
| Consumes    | internal/csvio |

## Questions

- None.

## Purpose

Malformed input is rejected before any output is produced. Rejection exits 3, writes nothing to
standard output, and writes one line to standard error naming the file and, for a record problem,
its line number.

## Behavior

1. An empty file, or a file with no records at all, is rejected.
2. A header name that is empty after trimming, or repeated after trimming, is rejected.
3. A record whose field count differs from the header is rejected, naming its line number.
4. A syntax error reported by `encoding/csv`, such as a bare quote in an unquoted field, is
   rejected with exit 3 and names the file and line number.
5. All output is buffered; nothing reaches standard output unless validation of the whole file
   succeeded.
6. A header-only file is valid and is not rejected.

## Required Go Tests

The build adds these tests in `internal/csvio` (names are exact): `TestRejectEmptyFile`,
`TestRejectBadHeader`, `TestRejectRaggedRecord`.
