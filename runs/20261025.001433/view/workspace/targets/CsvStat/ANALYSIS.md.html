Planning Instructions

Delivery Shape

CsvStat is a single-binary command-line profiler. The inputs are one CSV file path and optional --column, --freq, and --top options. Profile output is CSV on stdout with \n line endings. Diagnostics go to stderr. Exit codes are 0 (success), 1 (unreadable file), 2 (usage), and 3 (rejected input). The application root is a Go module (go.mod, go 1.22 or newer) whose main package lives at cmd/csvstat/. Module packages below the root are Plan's choice. There is no persistence and no network I/O.

Test and Acceptance Strategy

Focused story tests are go test cases written with the story. Each feature story runs only its slice with go test -run <pattern> ./... from the application root and declares Suite: scoped.

QA-002 is the single terminal verification story. It depends on every other story, runs sh sources/run.sh unfiltered, and declares Suite: full. Its acceptance is that every supplied check passes with zero failures. run.sh exposes no scope selector, so no other story executes it.

QA-001 proves bin/test.sh by sh -n and by reading its go vet and go test calls. It does not run the full suite. run.sh needs cmp, diff, mktemp, and sed on the path.

Program acceptance is finite and story-scoped. The project-level criteria in SEA_TRIALS.md carry the release gate.

Sequencing and Dependencies

  • CLI-001 has no dependency and comes first. INPUT-001 depends on CLI-001 for invocation, so the two form the first slice.
  • INPUT-002 and INPUT-003 depend on INPUT-001.
  • COUNTS-001 depends on INPUT-002.
  • TYPES-001, TYPES-002, and TYPES-003 depend on COUNTS-001.
  • STATS-001 depends on all three TYPES stories.
  • STATS-002 and STATS-003 depend on TYPES-001 and STATS-001.
  • STATS-004 depends on STATS-002 and STATS-003.

  • FREQ-001 depends on COUNTS-001 and CLI-001. FREQ-002 depends on FREQ-001 and CLI-002.
  • CLI-002 and CLI-003 depend on CLI-001.
  • QA-001 depends on INPUT-001.
  • QA-002 depends on QA-001 and every implementation story.
  • External dependencies: Go 1.22 or newer. No network or database.

Source Conflicts and Gaps

Cross-source conflicts: none. INSTRUCTIONS.md, sources/run.sh known answers, and the prior SEA_TRIALS.md agree. The known answers were spot-checked against the fixtures (employees id sum/mean/median, manager_id, notes distinct and max, sensors reading_id sum and battery, orders order_id sum, qty sum and median, customer frequencies, sensor frequency ties) and agree.

Gaps resolved by the narrowest behavior, not by questionnaire. These are persisted in Surfaced Acceptance Criteria:

  1. A CSV syntax error from encoding/csv exits 3 (AC-005). The sources list only ragged records under exit 3, so this is the nearest rejection code.
  2. --column and --freq names match trimmed header names exactly and case-sensitively (AC-002).
  3. Integer sums and means use arbitrary precision (AC-003).
  4. Number arithmetic is exact decimal, rounded only at output (AC-004).
  5. --help writes to stdout and exits 0 (AC-001). This is the CLI help-text baseline.
  6. A directory or unopenable path exits 1 (AC-006).
  7. Bytes are compared as bytes. No BOM stripping and no UTF-8 rejection (AC-007).

No measurement facts are missing. The sources contain no numeric release threshold, so no ## Questions entries are needed.
