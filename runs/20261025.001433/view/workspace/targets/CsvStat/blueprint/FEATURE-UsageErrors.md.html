FEATURE: Usage Errors

FieldValue
Version20261025 V1
DescriptionMaps every malformed command line to exit code 2 with nothing on standard output.
Depends OnFEATURE-CliParsing.md, ARCHITECTURE.md
Providesexit code 2
Consumescsvstat [--column <name>] <file>, csvstat --freq <name> [--top <n>] <file>

Purpose

Any command line that does not match one of the two command forms is a usage error.

Behavior

Exit code 2, nothing on standard output, and a diagnostic on standard error, for each of:

  • no file argument;
  • more than one file argument;
  • an unknown option;
  • an option missing its value (--column, --freq, or --top as the last argument);
  • --top not a positive integer;
  • --top without --freq;
  • --column together with --freq.

The flag set uses flag.ContinueOnError with its output directed to standard error, so the parser never writes to standard output on failure. Usage errors are decided before the file is opened, so a usage error for a missing file path never becomes exit 1. --help is not a usage error and is owned by FEATURE-CliParsing.md.

Programmatic Acceptance

=== AC usage-missing-or-extra-file ===
Intent: No file, or more than one file, exits 2 with empty standard output.
Suite: scoped
Requires: python-package=drydock_go; scope=test

import os

from drydock_go import cli_runner

orders = os.path.abspath("sources/orders.csv") sensors = os.path.abspath("sources/sensors.csv")

code, out, err = cli_runner() print(err) assert code == 2, (code, out, err) assert out == "", out

code, out, err = cli_runner(orders, sensors) print(err) assert code == 2, (code, out, err) assert out == "", out

code, out, err = cli_runner("--column", "qty", orders, sensors) print(err) assert code == 2, (code, out, err) assert out == "", out === END AC usage-missing-or-extra-file ===

User Acceptance

  • None.

Guardrails

  • A usage error never writes to standard output.
  • A usage error never exits 1 or 3.
  • Diagnostics go to standard error and are never compared.
