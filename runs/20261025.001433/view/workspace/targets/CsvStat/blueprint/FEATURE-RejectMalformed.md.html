FEATURE: Reject Malformed Input

FieldValue
Version20261025 V1
DescriptionReject empty files, bad header names, ragged records, and CSV syntax errors with exit code 3 and nothing on standard output.
Depends OnFEATURE-CsvReading.md, ARCHITECTURE.md
Providesexit code 3 for rejected input
Consumesinternal/csvio

Purpose

Malformed input is rejected before any output is produced. Rejection exits 3, writes nothing to standard output, and writes one line to standard error naming the file and, for a record problem, its line number.

Behavior

  1. An empty file, or a file with no records at all, is rejected.
  2. A header name that is empty after trimming, or repeated after trimming, is rejected.
  3. A record whose field count differs from the header is rejected, naming its line number.
  4. A syntax error reported by encoding/csv, such as a bare quote in an unquoted field, is

rejected with exit 3 and names the file and line number.

  1. All output is buffered; nothing reaches standard output unless validation of the whole file

succeeded.

  1. A header-only file is valid and is not rejected.

Required Go Tests

The build adds these tests in internal/csvio (names are exact): TestRejectEmptyFile, TestRejectBadHeader, TestRejectRaggedRecord.

=== AC reject-bad-header-names ===

User Acceptance

  • None.

Guardrails

  • A rejected input never produces partial standard output.
  • Only the diagnostic on standard error names the file and line; its wording is not a contract.
  • A header-only file is valid input and must not be rejected.
  • Standard library only.
