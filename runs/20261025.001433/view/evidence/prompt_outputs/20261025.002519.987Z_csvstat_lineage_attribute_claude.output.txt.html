<requirement name="csv-profiler-tool" stories="foundation,input-profile">
Build a command-line tool that profiles a CSV file. For every column it infers a type and reports
row, null, and distinct counts, the minimum and maximum, and for numeric columns the sum, mean, and
median.
</requirement>
<requirement name="list-frequent-values" stories="freq-list">
It also lists the most frequent values of one column.
</requirement>
<requirement name="command-forms" stories="cli-args">
csvstat [--column <name>] <file>
csvstat --freq <name> [--top <n>] <file>
</requirement>
<requirement name="column-option" stories="select-column">
`--column <name>` | Profile only the named column.
</requirement>
<requirement name="freq-option" stories="freq-list">
`--freq <name>` | List the most frequent values of the named column instead of profiling.
</requirement>
<requirement name="top-option" stories="freq-top">
`--top <n>` | With `--freq`, list at most `<n>` values. A positive integer; default `5`.
</requirement>
<requirement name="option-combinations" stories="cli-usage">
`--column` and `--freq` cannot be combined. `--top` is valid only with `--freq`.
</requirement>
<requirement name="trim-values" stories="input-trim">
Every header name and every value is trimmed of leading and trailing spaces before any other
rule applies.
</requirement>
<requirement name="reject-malformed-file" stories="input-reject">
The file is **rejected** when it is empty, when a header name is empty or repeated, or when any
record has a different number of fields from the header.
</requirement>
<requirement name="null-definition" stories="counts">
**Null.** A value is null when it is empty, or when it equals `NA`, `N/A`, or `NULL` ignoring
case. All other values are non-null.
</requirement>
<requirement name="type-inference-numeric" stories="types-numeric">
| `integer` | matches `-?[0-9]+` |
| `number` | matches `-?[0-9]+(\.[0-9]+)?` |
</requirement>
<requirement name="type-inference-date" stories="types-date">
| `date` | matches `YYYY-MM-DD` and is a real calendar date (`2025-02-30` is not) |
</requirement>
<requirement name="type-inference-other" stories="types-other">
| `boolean` | equals `true` or `false`, ignoring case |
| `text` | anything |

A column with no non-null values has type `empty`.
</requirement>
<requirement name="count-fields" stories="counts">
| `rows` | Number of data records. |
| `nulls` | Number of null values. |
| `distinct` | Number of different non-null values, compared as exact strings after trimming. |
</requirement>
<requirement name="min-max-fields" stories="stats-minmax">
| `min`, `max` | `integer`: the smallest and largest value as an integer. `number`: as a decimal. `date`: earliest and latest. `boolean`: `false` if any value is false, else `true`; `true` if any value is true, else `false`. `text`: smallest and largest by byte value. `empty`: empty. |
</requirement>
<requirement name="sum-mean-fields" stories="stats-summean">
| `sum` | `integer`: the integer total. `number`: the decimal total. Otherwise empty. |
| `mean` | `integer` and `number`: total divided by non-null count. Otherwise empty. |
</requirement>
<requirement name="median-field" stories="stats-median">
| `median` | `integer` and `number`: the middle value of the sorted non-null values, or the mean of the two middle values when the count is even. Otherwise empty. |
</requirement>
<requirement name="decimal-formatting" stories="stats-format">
**Decimals.** Every `number` `min`, `max`, and `sum`, and every `mean` and `median`, is written with
exactly two decimal places, rounded half away from zero from the exact value, with a leading `-`
when negative and no thousands separator: `1012.50`, `-12.21`, `0.00`. Integer `min`, `max`, and
`sum` are written as plain integers.
</requirement>
<requirement name="frequency-output" stories="freq-list,freq-top">
Header `value,count`, then one row per distinct non-null value of the column, ordered by count
descending, then value ascending by byte value, at most `--top` rows. Null values are not listed. A
column with no non-null values writes only the header.
</requirement>
<requirement name="output-format" stories="input-profile,input-reject">
CSV on standard output with `\n` line endings. A field that contains a comma, a double quote, or a
newline is quoted as RFC 4180 specifies; Go's `encoding/csv` writer produces this format. A
failing command writes nothing to standard output and one diagnostic line to standard error naming
the file and, for a rejected record, its line number.
</requirement>
<requirement name="exit-operational-failure" stories="cli-unreadable">
| `1` | Operational failure: the file cannot be opened or read. |
</requirement>
<requirement name="exit-usage-error" stories="cli-usage,cli-args">
| `2` | Usage error: missing or extra file, unknown option, missing option value, `--top` not a positive integer, `--top` without `--freq`, `--column` with `--freq`. |
</requirement>
<requirement name="exit-rejected" stories="input-reject,select-absent">
| `3` | Rejected: empty file, empty or repeated header name, ragged record, or a column name that is not in the header. |
</requirement>
<requirement name="test-runner" stories="qa-testrunner">
The completed application provides a POSIX-compatible `bin/test.sh` that runs `go vet ./...` and
`go test ./...` from the application root and exits zero only when both pass.
</requirement>
<requirement name="scoring-harness" stories="qa-verification">
The harness runs `go build -o <temporary path> ./cmd/csvstat` and then runs 22 checks. Each check
compares one command's exit code and standard output with a known answer.
</requirement>
