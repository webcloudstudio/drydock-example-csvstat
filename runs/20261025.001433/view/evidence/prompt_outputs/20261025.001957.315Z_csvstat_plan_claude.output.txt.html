# FEATURE: Profile Counts

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Report the rows, nulls, and distinct counts for every column of a CSV file. |
| Depends On  | FEATURE-ValueTrimming.md |
| Provides    | profile fields rows, nulls, distinct |
| Consumes    | trimmed header names and values from FEATURE-ValueTrimming.md |

## Questions

- None.

## Purpose

For each column, the profile row carries three counts computed from the trimmed values of that column: `rows`, `nulls`, and `distinct`. Later stories (types, statistics, frequency) reuse the null rule defined here.

## Behavior

- `rows` is the number of data records in the file (the header is not counted). Every column of a file reports the same `rows`.
- A value is **null** when, after trimming, it is empty or equals `NA`, `N/A`, or `NULL` ignoring case. Every other value is non-null.
- `nulls` is the number of null values in the column.
- `distinct` is the number of different non-null values in the column, compared as exact strings after trimming. Comparison is case-sensitive, so `Apple` and `apple` are two values. Null values are never counted.
- A file with a header and no data records reports `rows` 0, `nulls` 0, and `distinct` 0 for every column.
- The null rule is exposed as a single reusable function in `internal/profile` so that types, statistics, and frequency use one definition.
- All counts are computed from the file given. No count is hardcoded.

## Programmatic Acceptance

=== AC counts-rows-nulls-distinct ===
Intent: rows, nulls, and distinct are computed from the file, with padded values trimmed before comparison.

# FEATURE: Types Numeric

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Infer the integer and number column types from the non-null values of a column. |
| Depends On  | FEATURE-ProfileCounts.md |
| Provides    | profile field type values integer and number |
| Consumes    | null rule from FEATURE-ProfileCounts.md |

## Questions

- None.

## Purpose

A column's type is the first type in the order integer, number, date, boolean, text that every non-null value satisfies. This specification owns the first two members of that order.

## Behavior

- `integer`: every non-null value matches `-?[0-9]+` (the whole value, after trimming).
- `number`: every non-null value matches `-?[0-9]+(\.[0-9]+)?` (the whole value, after trimming) and the column is not `integer`.
- Matching is anchored at both ends. `+5`, `.5`, `5.`, `1e3`, `1,000`, and `0x10` match neither pattern.
- A single non-matching non-null value disqualifies the type for the column.
- Null values (see FEATURE-ProfileCounts.md) never disqualify a type.
- Leading zeros are permitted (`007` is an integer). Arbitrarily long digit strings are integers; no length limit applies.
- Matchers live in `internal/profile` and are hand-coded or use `regexp` anchored with `^` and `$`.

## Programmatic Acceptance

# FEATURE: Types Date

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Infer the date column type and reject values that are not real calendar dates. |
| Depends On  | FEATURE-ProfileCounts.md |
| Provides    | profile field type value date |
| Consumes    | null rule from FEATURE-ProfileCounts.md |

## Questions

- None.

## Purpose

A column is a `date` column when every non-null value is a real calendar date written `YYYY-MM-DD`. This specification owns the date test; the final type decision is composed in FEATURE-TypesOther.md.

## Behavior

- A value qualifies when, after trimming, it is exactly ten characters, matches `YYYY-MM-DD` (four digits, `-`, two digits, `-`, two digits), and names a real calendar date.
- A value such as `2025-02-30`, `2025-13-01`, or `2025-00-10` does not qualify. `2024-02-29` qualifies (leap year); `2025-02-29` does not.
- One non-qualifying non-null value makes the column not `date`; the column then falls through to the next type in order.
- Null values never disqualify the type.
- A column of integers or numbers is typed by FEATURE-TypesNumeric.md before the date test applies; a date value never matches the integer or number patterns.
- Implementation uses `time.Parse` with layout `2006-01-02` plus a length check so that non-padded forms such as `2025-2-3` are rejected.

## Programmatic Acceptance

# FEATURE: Types Other

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Infer the boolean, text, and empty column types and compose the final type decision. |
| Depends On  | FEATURE-TypesNumeric.md, FEATURE-TypesDate.md |
| Provides    | profile field type values boolean, text, empty |
| Consumes    | integer and number tests from FEATURE-TypesNumeric.md, date test from FEATURE-TypesDate.md |

## Questions

- None.

## Purpose

Complete the type vocabulary and compose the single type decision reported in the `type` field of each profile row.

## Behavior

- `boolean`: every non-null value equals `true` or `false`, ignoring case (`True`, `FALSE`, `tRuE` qualify). Values such as `yes`, `1`, `t` do not.
- `text`: no earlier type fits.
- `empty`: the column has no non-null value (including a column of zero data records).
- The final type is the first of `integer`, `number`, `date`, `boolean`, `text` that every non-null value satisfies; `empty` replaces that decision when no non-null value exists.
- A column mixing types, such as integers and dates, or numbers and booleans, is `text`.
- The decision is a single function in `internal/profile` that the statistics stories branch on.

# FEATURE: Min Max

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Report the min and max profile fields for every column type. |
| Depends On  | FEATURE-TypesOther.md |
| Provides    | profile fields min, max |
| Consumes    | column type decision from FEATURE-TypesOther.md |

## Questions

- None.

## Purpose

Each profile row reports the smallest and largest non-null value of its column, interpreted according to the column's type.

## Behavior

- `integer`: the smallest and largest value as numbers, written as plain integers (`-3` before `12`). Comparison is numeric, not lexical, and is exact (`math/big`), so digit strings of any length are safe.
- `number`: the smallest and largest value by exact decimal comparison. Output formatting to exactly two decimals is owned by FEATURE-DecimalFormat.md; this story supplies the exact values.
- `date`: the earliest and latest value (`YYYY-MM-DD` strings order chronologically).
- `boolean`: `min` is `false` if any value is false, else `true`; `max` is `true` if any value is true, else `false`. Output is lower-case regardless of input case.
- `text`: the smallest and largest value by byte value (not locale, not case-folded), after trimming.
- `empty`: both fields are blank.
- Null values are ignored. Blank is the empty string.
- Min and max are computed from the file examined; nothing is hardcoded.

## Programmatic Acceptance

=== AC minmax-integer ===
Intent: Integer min and max are compared numerically and written as plain integers.

import csv
import io
import os
import tempfile

from drydock_go import cli_runner


def profile(lines):
    with tempfile.TemporaryDirectory() as d:
        path = os.path.join(d, "in.csv")
        with open(path, "w", newline="") as f:
            f.write("".join(line + "\n" for line in lines))
        code, out, err = cli_runner(path)
    print(out)
    print(err)
    assert code == 0, (code, out, err)
    return {r["column"]: r for r in csv.DictReader(io.StringIO(out))}


values = [9, 100, -3, 42, 7]
lines = ["id,v"] + [f"{i},{v}" for i, v in enumerate(values)]
lines.append("99,NA")
rows = profile(lines)
assert rows["v"]["type"] == "integer"
assert rows["v"]["min"] == str(min(values))
assert rows["v"]["max"] == str(max(values))
=== END AC minmax-integer ===

=== AC minmax-boolean ===
Intent: Boolean min is false when any value is false and max is true when any value is true; a single-valued column reports that value for both.

import csv
import io
import os
import tempfile

from drydock_go import cli_runner


def profile(lines):
    with tempfile.TemporaryDirectory() as d:
        path = os.path.join(d, "in.csv")
        with open(path, "w", newline="") as f:
            f.write("".join(line + "\n" for line in lines))
        code, out, err = cli_runner(path)
    print(out)
    print(err)
    assert code == 0, (code, out, err)
    return {r["column"]: r for r in csv.DictReader(io.StringIO(out))}


mixed = ["True", "FALSE", "true"]
only_true = ["True", "TRUE", "true"]
only_false = ["False", "FALSE", "false"]
lines = ["m,t,f"] + [f"{a},{b},{c}" for a, b, c in zip(mixed, only_true, only_false)]
rows = profile(lines)
assert rows["m"]["min"] == "false" and rows["m"]["max"] == "true"
assert rows["t"]["min"] == "true" and rows["t"]["max"] == "true"
assert rows["f"]["min"] == "false" and rows["f"]["max"] == "false"
=== END AC minmax-boolean ===

=== AC minmax-text-bytes ===
Intent: Text min and max compare by byte value, so upper-case sorts before lower-case, and padding is trimmed.

import csv
import io
import os
import tempfile

from drydock_go import cli_runner


def profile(lines):
    with tempfile.TemporaryDirectory() as d:
        path = os.path.join(d, "in.csv")
        with open(path, "w", newline="") as f:
            f.write("".join(line + "\n" for line in lines))
        code, out, err = cli_runner(path)
    print(out)
    print(err)
    assert code == 0, (code, out, err)
    return {r["column"]: r for r in csv.DictReader(io.StringIO(out))}


values = ["banana", "Zebra", "apple", "  Acme Corp ", "mentor"]
lines = ["id,v"] + [f"{i},{v}" for i, v in enumerate(values)]
rows = profile(lines)
assert rows["v"]["type"] == "text"
trimmed = [v.strip() for v in values]
assert rows["v"]["min"] == min(trimmed, key=lambda s: s.encode())
assert rows["v"]["max"] == max(trimmed, key=lambda s: s.encode())
=== END AC minmax-text-bytes ===

=== AC minmax-empty-and-nulls ===
Intent: An empty column reports blank min and max, and nulls are ignored when choosing extremes.

import csv
import io
import os
import tempfile

from drydock_go import cli_runner


def profile(lines):
    with tempfile.TemporaryDirectory() as d:
        path = os.path.join(d, "in.csv")
        with open(path, "w", newline="") as f:
            f.write("".join(line + "\n" for line in lines))
        code, out, err = cli_runner(path)
    print(out)
    print(err)
    assert code == 0, (code, out, err)
    return {r["column"]: r for r in csv.DictReader(io.StringIO(out))}


values = [5, 2, 9]
lines = ["id,v,gap"] + [f"{i},{v},NULL" for i, v in enumerate(values)]
lines.append("77,NA,")
rows = profile(lines)
assert rows["gap"]["type"] == "empty"
assert rows["gap"]["min"] == ""
assert rows["gap"]["max"] == ""
assert rows["v"]["min"] == str(min(values))
assert rows["v"]["max"] == str(max(values))
=== END AC minmax-empty-and-nulls ===

## User Acceptance

- None.

## Guardrails

- Min and max are computed from the file examined; no extreme is hardcoded.
- Integer and number comparison is exact; no binary floating point is used.
- Text comparison is by byte value, never locale or case folding.
- Standard library only.
