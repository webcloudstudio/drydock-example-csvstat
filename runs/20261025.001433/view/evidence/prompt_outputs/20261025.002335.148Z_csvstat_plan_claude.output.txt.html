# FEATURE: Frequency Listing

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Lists the most frequent non-null values of one named column with --freq. |
| Depends On  | ARCHITECTURE.md, FEATURE-ProfileCounts.md, FEATURE-CliParsing.md |
| Provides    | value,count output |
| Consumes    | csvstat --freq <name> <file> |

## Questions

- None.

## Purpose

`csvstat --freq <name> <file>` writes a two-column CSV of the distinct non-null values of the named
column and how often each occurs, instead of the profile.

## Behavior

- Header line is `value,count`.
- One row per distinct non-null value, ordered by count descending, then by value ascending by byte
  value.
- Values are trimmed before counting and compared as exact strings. Null values (empty, or `NA`,
  `N/A`, `NULL` ignoring case) are not listed.
- A column with no non-null values writes only the header.
- At most the `--top` limit of rows is written; the default limit is 5 (the limit itself is owned by
  FEATURE-FrequencyTop.md).
- Output is CSV with `\n` line endings, written with `encoding/csv`, and only after the whole file
  has been read and validated.
- Success exits 0.

## Programmatic Acceptance

=== AC freq-department ===
Intent: Frequencies for a text column are counted, ordered by count then byte value, and parsed back as CSV.
Suite: scoped
Requires: python-package=drydock_go; scope=test

import csv
import io
import os
from collections import Counter

from drydock_go import cli_runner

path = os.path.abspath("sources/employees.csv")
col = "department"
top = 5
with open(path, newline="") as fh:
    rows = list(csv.reader(fh))
header = [h.strip() for h in rows[0]]
idx = header.index(col)
vals = [r[idx].strip() for r in rows[1:]]
vals = [v for v in vals if v != "" and v.upper() not in ("NA", "N/A", "NULL")]
ordered = sorted(Counter(vals).items(), key=lambda kv: (-kv[1], kv[0].encode()))
want = [[v, str(c)] for v, c in ordered[:top]]

code, out, err = cli_runner("--freq", col, path)
print(out)
print(err)
assert code == 0, (code, out, err)
got = list(csv.reader(io.StringIO(out)))
assert got[0] == ["value", "count"], got
assert got[1:] == want, (got[1:], want)

# FEATURE: Frequency Limit

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Limits frequency output with --top, defaulting to 5 and accepting a positive integer only. |
| Depends On  | FEATURE-Frequency.md, FEATURE-UsageErrors.md, ARCHITECTURE.md |
| Provides    | csvstat --freq <name> --top <n> <file> |
| Consumes    | value,count output |

## Questions

- None.

## Purpose

`--top <n>` bounds how many rows `--freq` writes.

## Behavior

- Default limit is 5 when `--top` is absent.
- `--top` accepts a positive integer only. Zero, negative numbers, non-numeric text, and an empty
  value are usage errors (exit 2, nothing on standard output).
- When fewer distinct non-null values exist than the limit, all of them are written.
- `--top` without `--freq` is a usage error (exit 2, nothing on standard output).
- A very large positive integer that fits no machine int is accepted as unbounded rather than
  rejected.

# FEATURE: Usage Errors

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Maps every malformed command line to exit code 2 with nothing on standard output. |
| Depends On  | FEATURE-CliParsing.md, ARCHITECTURE.md |
| Provides    | exit code 2 |
| Consumes    | csvstat [--column <name>] <file>, csvstat --freq <name> [--top <n>] <file> |

## Questions

- None.

## Purpose

Any command line that does not match one of the two command forms is a usage error.

## Behavior

Exit code 2, nothing on standard output, and a diagnostic on standard error, for each of:

- no file argument;
- more than one file argument;
- an unknown option;
- an option missing its value (`--column`, `--freq`, or `--top` as the last argument);
- `--top` not a positive integer;
- `--top` without `--freq`;
- `--column` together with `--freq`.

The flag set uses `flag.ContinueOnError` with its output directed to standard error, so the parser
never writes to standard output on failure. Usage errors are decided before the file is opened, so
a usage error for a missing file path never becomes exit 1. `--help` is not a usage error and is
owned by FEATURE-CliParsing.md.

# FEATURE: Unreadable File

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Maps a file that cannot be opened or read to exit code 1 with nothing on standard output. |
| Depends On  | FEATURE-CliParsing.md, ARCHITECTURE.md |
| Provides    | exit code 1 |
| Consumes    | csvstat [--column <name>] <file>, csvstat --freq <name> [--top <n>] <file> |

## Questions

- None.

## Purpose

An operational failure to obtain the input is reported as exit 1, distinct from a usage error (2)
and from rejected content (3).

## Behavior

- A path that does not exist, cannot be opened, is a directory, or fails while being read exits 1.

  and a malformed one is exit 2.

# FEATURE: Test Runner

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Provides a POSIX sh bin/test.sh that runs go vet and go test and exits zero only when both pass. |
| Depends On  | FEATURE-CsvReading.md, ARCHITECTURE.md |
| Provides    | bin/test.sh |
| Consumes    | go vet ./..., go test ./... |

## Questions

- None.

## Purpose

`bin/test.sh` is the single entry point for the project's automated checks.

## Behavior

- POSIX sh only: no bash-isms, and it passes `sh -n bin/test.sh`.
- It changes to the application root (the parent of `bin/`) so it works from any directory.
- It runs `go vet ./...` and then `go test ./...`, and exits zero only when both exit zero. A
  failure of either exits non-zero; a vet failure does not let the test run mask it.
- It uses whatever `go` is on `PATH` and never a vendored toolchain.
- The Go test suite it runs covers each type, each statistic, null handling, rounding, each output
  form, and each exit code, using files the tests write themselves (not the files under `sources/`).

## Programmatic Acceptance

import os
import subprocess
import tempfile

with tempfile.TemporaryDirectory() as tmp:
    log = os.path.join(tmp, "calls.log")
    stub = os.path.join(tmp, "go")
    with open(stub, "w") as fh:
        fh.write('#!/bin/sh\necho "$1" >> "$GO_LOG"\n[ "$1" = "$FAIL_ON" ] && exit 1\nexit 0\n')
    os.chmod(stub, 0o755)
    env = {**os.environ, "PATH": tmp + os.pathsep + os.environ["PATH"], "GO_LOG": log, "FAIL_ON": "none"}
    result = subprocess.run(["sh", "bin/test.sh"], capture_output=True, text=True, env=env)
    print(result.stdout)
    print(result.stderr)
    assert result.returncode == 0
    with open(log) as fh:
        calls = fh.read().split()
    assert "vet" in calls, calls
    assert "test" in calls, calls
