# ARCHITECTURE: CsvStat

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Module layout, package boundaries, and technical decisions for the CsvStat command-line CSV profiler. |
| Depends On  | None |
| Provides    | go.mod, cmd/csvstat, internal/cli Run |

## Questions

- None.

## Purpose

CsvStat is a single-binary Go command-line tool. It reads one CSV file, infers a type per column,
and writes either a profile CSV or a frequency CSV to standard output. Failures write nothing to
standard output, one diagnostic line to standard error, and exit with a distinct code.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`; that file is the decision of record.

| Technology | Where it applies |
|---|---|
| Go 1.22 or newer, standard library only | Every package; no third-party module in `go.mod` |
| go test and go vet | Automated tests and `bin/test.sh` |
| CSV (`encoding/csv`) | Reading the input file and writing all standard output |
| POSIX sh | `bin/test.sh` and the supplied grader |

## Module Layout

```text
go.mod                    module csvstat, go 1.22 or newer, no require lines
cmd/csvstat/main.go       package main: calls cli.Run(os.Args[1:], os.Stdout, os.Stderr) and os.Exit
internal/cli              Run(args []string, stdout, stderr io.Writer) int; argument parsing, exit codes
internal/reader           Read, IsNull, ErrRejected; file reading, trimming, validation, null rule
internal/infer            Infer; column type inference
internal/stats            counts, min, max, sum, mean, median using math/big
internal/format           FormatDecimal; two-decimal half-away-from-zero formatting
internal/output           profile and frequency CSV writers
bin/test.sh               POSIX sh: go vet ./... then go test ./...
```

Only `main` calls `os.Exit`. `cli.Run` uses a local `flag.FlagSet` with `flag.ContinueOnError` and
discarded flag output, and is tested with `bytes.Buffer`.

## Data Flow

1. `cli.Run` parses and validates arguments (usage errors exit 2 before the file is opened).
2. `reader.Read` opens the file; failure to open or read exits 1.
3. `reader.Read` parses with `encoding/csv`, trims, and validates; rejection exits 3.
4. `infer.Infer` types each column from its non-null values.
5. `stats` computes exact values; `format` rounds once when writing.
6. `output` writes CSV with `\n` line endings to standard output; exit 0.

Output is assembled in memory and written only after every step succeeds, so a failing command
never writes to standard output.

## Exit Codes

| Code | Meaning |
|---|---|
| 0 | Success |
| 1 | File cannot be opened or read |
| 2 | Usage error |
| 3 | Rejected input: empty file, empty or repeated header name, ragged record, unknown column name |

## Technical Decisions

- Sums, means, and medians use `math/big` rationals and are rounded once, half away from zero.
- Application code never reads `sources/run.sh` or any supplied data file and embeds no statistic.
- Diagnostics go to standard error and are never compared.

## Module Ownership

| Boundary | Owning module | Low-level APIs allowed |
|---|---|---|
| Input file access | `internal/reader` | `os.Open`, `encoding/csv` reader |
| Standard output | `internal/output` | `encoding/csv` writer |
| Process exit | `cmd/csvstat` | `os.Exit` |
| Persistence, configuration, file store, external services | None; the tool has none | None |

# FEATURE: Command Line Arguments

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Parse the csvstat options that precede exactly one file argument and reject malformed argument lists with exit 2. |
| Depends On  | ARCHITECTURE.md |
| Provides    | --column, --freq, --top parsing |

## Questions

- None.

## Purpose

`cli.Run` accepts these forms:

```text
csvstat [--column <name>] <file>
csvstat --freq <name> [--top <n>] <file>
```

Options precede the file and exactly one file is required. Parsing uses a local `flag.FlagSet`
with `flag.ContinueOnError` and discarded flag output. Arguments are validated before the file is
opened, so a usage error never depends on the file's existence.

## Behavior

| Input | Result |
|---|---|
| No arguments | exit 2 |
| Two or more positional arguments | exit 2 |
| Unknown option | exit 2 |
| Option with no value (`--column`, `--freq`, `--top` as last argument) | exit 2 |
| `--top` not a positive integer (`0`, negative, non-numeric) | exit 2 |
| `--top` without `--freq` | exit 2 |
| `--column` together with `--freq` | exit 2 |
| Option placed after the file | the option is an extra positional argument: exit 2 (decision Q-001) |

Every usage error writes nothing to standard output and one diagnostic line to standard error.
`--top` defaults to 5 when `--freq` is given alone. The parsed result carries the column name, the
frequency column, the top count, and the file path for the command stories that follow.

# FEATURE: CSV Reading

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Read a UTF-8 RFC 4180 CSV file with trimmed header and values and reject malformed files. |
| Depends On  | ARCHITECTURE.md |
| Provides    | reader.Read, ErrRejected |

## Questions

- None.

## Purpose

Package `internal/reader` opens a file and returns a table: the header names and the data records,
all trimmed of leading and trailing spaces.

## Behavior

1. The file is UTF-8 CSV as RFC 4180 defines it, read with `encoding/csv`. The first record is the header.
2. The reader sets `FieldsPerRecord = -1` so a ragged record is detected by this package and reported with its line number.
3. Every header name and every value is trimmed of leading and trailing spaces before any other rule applies.
4. The file is rejected when it is empty, when a header name is empty after trimming, when a header name repeats, or when any record has a different field count from the header.
5. A CSV syntax error from `encoding/csv`, such as a bare quote, is also a rejection (decision Q-003).
6. A header with no data records is valid and yields zero rows.
7. A rejection returns an error that satisfies `errors.Is(err, reader.ErrRejected)` and carries the file name and, for a record-level rejection, the record's line number. The `cli` package maps it to exit 3.
8. A file that cannot be opened or read returns an error that is not `ErrRejected`; the `cli` package maps it to exit 1.
9. Quoted fields may contain commas, quotes, and newlines.

## Required Go tests

The build writes these tests in `internal/reader`, each writing its own file under `t.TempDir()`:

| Test | Proves |
|---|---|
| `TestReadTrimsHeaderAndValues` | padded header names and values are trimmed |
| `TestReadQuotedComma` | a quoted field containing a comma is one value |
| `TestReadHeaderOnly` | a header with no records yields zero rows |
| `TestReadRejectsEmptyFile` | a zero-byte file is `ErrRejected` |
| `TestReadRejectsEmptyHeaderName` | an empty header name is `ErrRejected` |
| `TestReadRejectsRepeatedHeaderName` | a repeated header name is `ErrRejected` |
| `TestReadRejectsRaggedRecord` | a record with an extra field is `ErrRejected` and its message names the line number |
| `TestReadMissingFileIsNotRejected` | an unopenable file is an error that is not `ErrRejected` |

# FEATURE: Null Values

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Classify a trimmed value as null when it is empty or equals NA, N/A, or NULL ignoring case. |
| Depends On  | FEATURE-CsvReading.md |

## Questions

- None.

## Purpose

Package `internal/reader` exports `IsNull(value string) bool`. Values are already trimmed by the
reader. All other statistics treat null values as absent from type inference, distinct counts,

# FEATURE: Numeric Types

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Infer integer and number column types, testing integer before number. |
| Depends On  | FEATURE-NullValues.md |
| Provides    | InferType integer, number |

## Questions

- None.

## Purpose

Package `internal/infer` exports `Infer(values []string) string`, where `values` are the trimmed
values of one column. A column's type is the first matching type, in order, that every non-null
value satisfies. This story implements `integer` and `number`; later stories add `date`, `boolean`,
`text`, and `empty` to the same function. Until they land, a column matching neither numeric type
returns `text`.

## Behavior

- `integer`: every non-null value matches `-?[0-9]+`.
- `number`: every non-null value matches `-?[0-9]+(\.[0-9]+)?`.
- `integer` is tested before `number`, so a column of whole numbers is `integer` and one containing any decimal value is `number`.
- Null values (per `IsNull`) are skipped.
- No leading `+`, no exponent, no `1.`, no `.5`, no thousands separator, and no surrounding text match either type.
- A column mixing numeric and non-numeric values does not match.
- Examples from the supplied data: a column of ids is integer, a column of prices with two decimals is number, a column containing `A7` and `12.5` is not numeric.

## Required Go tests

Written in `internal/infer`:

| Test | Proves |
|---|---|
| `TestInferInteger` | whole numbers including negatives are integer |
| `TestInferNumberWhenAnyDecimal` | one decimal value among whole numbers makes number |
| `TestIntegerWinsOverNumber` | a column satisfying both is integer |
| `TestInferSkipsNulls` | null values do not prevent a numeric type |
| `TestInferRejectsMalformedNumbers` | `1.`, `.5`, `+1`, `1e3`, `1,5`, and `12abc` are neither integer nor number |
| `TestInferMixedIsNotNumeric` | a column with a numeric and a non-numeric value is neither type |
