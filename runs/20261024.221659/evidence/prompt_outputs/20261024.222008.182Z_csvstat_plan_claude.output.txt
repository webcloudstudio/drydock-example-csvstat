# FEATURE: Date Type Inference

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Infer the date column type from YYYY-MM-DD values that are real calendar dates. |
| Depends On  | FEATURE-NumericTypes.md |
| Provides    | InferType date |

## Questions

- None.

## Purpose

After integer and number have been ruled out for a column, the column is `date` when every non-null
value matches `YYYY-MM-DD` and names a real calendar date. A value such as `2025-02-30` has the right
shape but is not a calendar date, so it fails the date test and the column falls through to the next
candidate type (`boolean`, then `text`).

## Trigger

Type inference runs once per column after the file has been read, trimmed, and nulls classified.

## Sequence

1. Take the trimmed non-null values of the column.
2. If every value is an integer, or every value is a number, the earlier types win (FEATURE-NumericTypes.md).
3. Otherwise test each value: exactly four digits, a hyphen, two digits, a hyphen, two digits.
4. Validate the year, month, and day as a real calendar date, with leap years honored
   (`2024-02-29` is valid, `2025-02-29` is not). `time.Parse` with layout `2006-01-02` plus the
   strict shape check is sufficient.
5. The column is `date` only when every non-null value passes. Otherwise inference continues.

## Reads

- Trimmed non-null values of one column.

## Writes

- The inferred type token `date` for the column. Nothing is persisted.

## Acceptance Notes

- Single-digit month or day (`2025-2-3`) is not the `YYYY-MM-DD` shape and is not a date.
- Month 00 or 13 and day 00 are not dates.
- Null values never disqualify a date column.
- A column that mixes dates and other values is not a date column.

# FEATURE: Boolean, Text, and Empty Type Inference

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Infer the boolean, text, and empty column types as the last steps of type inference. |
| Depends On  | FEATURE-DateType.md |
| Provides    | InferType boolean, InferType text, InferType empty |

## Questions

- None.

## Purpose

Complete the type inference order `integer`, `number`, `date`, `boolean`, `text`, plus the special
`empty` type. A column is `boolean` when every non-null value equals `true` or `false` ignoring case.
Any column that satisfies no earlier type is `text`. A column with no non-null values at all is `empty`.

## Trigger

Type inference runs once per column after reading, trimming, and null classification.

## Sequence

1. If the column has zero non-null values, its type is `empty`, and the `min`, `max`, `sum`, `mean`,
   and `median` fields are written empty.
2. Otherwise apply `integer`, `number`, `date` in order (earlier features).
3. If every non-null value, compared case-insensitively, is `true` or `false`, the type is `boolean`.
4. Otherwise the type is `text`.

## Reads

- Trimmed non-null values of one column.

## Writes

- The inferred type token for the column (`boolean`, `text`, or `empty`). Nothing is persisted.

## Acceptance Notes

- `1` and `0` are integers, never booleans.
- `yes` and `no` are text.
- A value consisting only of spaces is trimmed to empty and is null.
- A file with a header and no rows gives every column the type `empty` with zero counts.
- Every `empty` column writes empty `min`, `max`, `sum`, `mean`, and `median`.

## Programmatic Acceptance

# FEATURE: Row, Null, and Distinct Counts

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Report the rows, nulls, and distinct count of every column. |
| Depends On  | FEATURE-BooleanTextTypes.md |
| Provides    | stats rows, stats nulls, stats distinct |

## Questions

- None.

## Purpose

For every column the profile reports three counts: `rows` (data records), `nulls` (null values), and
`distinct` (different non-null values). They are computed from the trimmed values of the column.

## Trigger

Computed once per column when the profile is built.

## Sequence

1. `rows` is the number of data records, excluding the header. It is the same for every column.
2. `nulls` counts values that are empty or equal `NA`, `N/A`, or `NULL` ignoring case after trimming.
3. `distinct` counts the different non-null values, compared as exact strings after trimming. Case
   differs, so `Acme` and `acme` are two values. `Globex` and `  Globex  ` are one value.

## Reads

- Trimmed values of one column.

## Writes

- Three integer fields written as plain decimal integers.

## Acceptance Notes

- A header-only file gives `rows`, `nulls`, and `distinct` of zero for every column.
- A null never contributes to `distinct`.
- A quoted field containing a comma is one value.

## Programmatic Acceptance

# FEATURE: Decimal Formatting

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Format exact decimal statistics with two places, rounded once half away from zero. |
| Depends On  | ARCHITECTURE.md |
| Provides    | FormatDecimal |

## Questions

- None.

## Purpose

Every `number` column `min`, `max`, and `sum`, and every `mean` and `median` of an integer or number
column, is written with exactly two decimal places. The value is held exactly as a `math/big` rational
and rounded once at output, half away from zero. Integer `min`, `max`, and `sum` are written as plain
integers.

## Trigger

Called whenever a profile field holds a decimal value.

## Sequence

1. Take the exact value as a `*big.Rat`.
2. Multiply by 100, then round to an integer with ties going away from zero (for example `0.005`
   becomes `0.01` and `-0.005` becomes `-0.01`).
3. Write the integer part, a decimal point, and exactly two fraction digits. No thousands separator.
4. Write a leading `-` only when the rounded result is non-zero and negative. A value that rounds to
   zero is written `0.00` with no sign (decision Q-002).

## Reads

- An exact rational value.

## Writes

- A string of the form `-?[0-9]+\.[0-9]{2}`.

## Acceptance Notes

- Rounding happens once, on the exact value, never on an already rounded intermediate and never through
  `float64`.
- `1012.50`, `-12.21`, and `0.00` are well formed outputs.
- The mean of `0.01` and `0.02` is exactly `0.015` and is written `0.02`.

## Programmatic Acceptance

- None.

- A header-only file gives `rows`, `nulls`, and `distinct` of zero for every column.
- A null never contributes to `distinct`.
- A quoted field containing a comma is one value.
