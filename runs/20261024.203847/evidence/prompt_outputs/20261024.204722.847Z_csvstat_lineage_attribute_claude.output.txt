<requirement name="go-stdlib-module" stories="foundation,module-build">
Implement in Go 1.22 or newer using only the standard library. The application root is a Go module, and its executable is the main package at `./cmd/csvstat`. Tests run under `go test`.
</requirement>
<requirement name="run-harness" stories="verification">
`sources/run.sh` is the scoring entry point. It is supplied, not authored, and is staged verbatim into the application root with the data files. `drydock uat` runs `sh sources/run.sh` from the completed application root and takes its exit code and output as the score.
</requirement>
<requirement name="command-options" stories="cli-options">
csvstat [--column <name>] <file>
csvstat --freq <name> [--top <n>] <file>
</requirement>
<requirement name="column-option" stories="column-select">
`--column <name>` | Profile only the named column.
</requirement>
<requirement name="freq-top-options" stories="cli-options,frequencies">
`--freq <name>` | List the most frequent values of the named column instead of profiling.
</requirement>
<requirement name="option-combinations" stories="usage-errors,cli-options">
`--column` and `--freq` cannot be combined. `--top` is valid only with `--freq`.
</requirement>
<requirement name="read-csv" stories="csv-reading">
The file is UTF-8 CSV as RFC 4180 defines it, read with Go's `encoding/csv`. The first record is the header.
</requirement>
<requirement name="trim-values" stories="null-trim">
Every header name and every value is trimmed of leading and trailing spaces before any other rule applies.
</requirement>
<requirement name="reject-malformed-file" stories="reject-malformed">
The file is **rejected** when it is empty, when a header name is empty or repeated, or when any record has a different number of fields from the header.
</requirement>
<requirement name="null-values" stories="null-trim,row-counts">
**Null.** A value is null when it is empty, or when it equals `NA`, `N/A`, or `NULL` ignoring case. All other values are non-null.
</requirement>
<requirement name="type-inference" stories="type-inference,date-type">
A column's type is the first of these that every non-null value satisfies:
</requirement>
<requirement name="empty-type" stories="type-inference">
A column with no non-null values has type `empty`.
</requirement>
<requirement name="profile-output" stories="csv-output,column-select,row-counts,type-inference">
Header `column,type,rows,nulls,distinct,min,max,sum,mean,median`, then one row per column in file order (or the one named by `--column`).
</requirement>
<requirement name="count-fields" stories="row-counts">
`rows` | Number of data records. `nulls` | Number of null values. `distinct` | Number of different non-null values, compared as exact strings after trimming.
</requirement>
<requirement name="min-max-fields" stories="min-max">
`min`, `max` | `integer`: the smallest and largest value as an integer. `number`: as a decimal. `date`: earliest and latest. `boolean`: `false` if any value is false, else `true`; `true` if any value is true, else `false`. `text`: smallest and largest by byte value. `empty`: empty.
</requirement>
<requirement name="numeric-stat-fields" stories="numeric-stats">
`sum` | `integer`: the integer total. `number`: the decimal total. Otherwise empty. `mean` | `integer` and `number`: total divided by non-null count. Otherwise empty. `median` | `integer` and `number`: the middle value of the sorted non-null values, or the mean of the two middle values when the count is even. Otherwise empty.
</requirement>
<requirement name="decimal-formatting" stories="numeric-stats,min-max">
**Decimals.** Every `number` `min`, `max`, and `sum`, and every `mean` and `median`, is written with exactly two decimal places, rounded half away from zero from the exact value, with a leading `-` when negative and no thousands separator: `1012.50`, `-12.21`, `0.00`. Integer `min`, `max`, and `sum` are written as plain integers.
</requirement>
<requirement name="frequency-output" stories="frequencies,csv-output">
Header `value,count`, then one row per distinct non-null value of the column, ordered by count descending, then value ascending by byte value, at most `--top` rows. Null values are not listed. A column with no non-null values writes only the header.
</requirement>
<requirement name="output-format" stories="csv-output">
CSV on standard output with `\n` line endings. A field that contains a comma, a double quote, or a newline is quoted as RFC 4180 specifies; Go's `encoding/csv` writer produces this format.
</requirement>
<requirement name="failure-diagnostics" stories="usage-errors,reject-malformed,unreadable-file">
A failing command writes nothing to standard output and one diagnostic line to standard error naming the file and, for a rejected record, its line number.
</requirement>
<requirement name="exit-unreadable" stories="unreadable-file">
`1` | Operational failure: the file cannot be opened or read.
</requirement>
<requirement name="exit-usage" stories="usage-errors,cli-options">
`2` | Usage error: missing or extra file, unknown option, missing option value, `--top` not a positive integer, `--top` without `--freq`, `--column` with `--freq`.
</requirement>
<requirement name="exit-rejected" stories="reject-malformed,column-select">
`3` | Rejected: empty file, empty or repeated header name, ragged record, or a column name that is not in the header.
</requirement>
<requirement name="test-script" stories="test-script">
The completed application provides a POSIX-compatible `bin/test.sh` that runs `go vet ./...` and `go test ./...` from the application root and exits zero only when both pass. The suite covers each type, each statistic, null handling, rounding, each output form, and each exit code using files written by the tests.
</requirement>
