# FEATURE: Reject Malformed Input

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Reject empty files, empty or repeated header names, and ragged records with exit code 3 and no standard output. |
| Depends On  | FEATURE-NullTrim.md, ARCHITECTURE.md |
| Provides    | exit 3 on rejected input |
| Consumes    | reader.Read, reader.Trim |

## Questions

- None.

## Purpose

After the file is read and trimmed, csvstat validates its shape. A rejected file exits 3, writes nothing to standard output, and writes one diagnostic line to standard error naming the file and, for a ragged record, its line number.

## Rejection Rules

1. The file is empty (no records at all).
2. A header name is empty after trimming.
3. A header name repeats another after trimming (exact comparison).
4. Any data record has a different number of fields from the header.

Field-count checking is done here, not by `encoding/csv`, so the diagnostic can name the offending line. A header-only file (header and no records) is valid and is not rejected.

## Behavior

- Validation runs before any statistic is computed, so no partial output is ever written.
- Exit code is 3 for every rejection above.
- Standard output is empty on rejection.
- Standard error carries one diagnostic line with the file path and, for a ragged record, the line number.

## Purpose

An operational failure to open or read the file is distinct from a malformed file. It exits 1, writes nothing to standard output, and writes one diagnostic line to standard error naming the file.

# FEATURE: CLI Options

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Parse the --column, --freq, and --top options and the single file argument into a request value. |
| Depends On  | ARCHITECTURE.md |
| Provides    | --column, --freq, --top |
| Consumes    | cli.Run |

## Questions

- None.

## Purpose

`internal/cli` parses arguments with a local `flag.FlagSet` created with `flag.ContinueOnError` and produces a request value that the profile and frequency stories consume. This story owns the accepted forms; the rejection of invalid forms belongs to the usage-errors story.

## Command Forms

```text
csvstat [--column <name>] <file>
csvstat --freq <name> [--top <n>] <file>
```

| Option | Meaning |
|---|---|
| `--column <name>` | Profile only the named column. |
| `--freq <name>` | List the most frequent values of the named column instead of profiling. |
| `--top <n>` | With `--freq`, list at most `<n>` values. A positive integer; default `5`. |

## Behavior

- Options precede exactly one file argument.
- With no option, every column is profiled.
- `--column <name>` produces a profile containing only that column.
- `--freq <name>` produces the frequency list with header `value,count`.
- `--top` defaults to 5 when `--freq` is given without it.
- The parsed request carries: file path, column name (optional), freq name (optional), and top count.
- Only `main` calls `os.Exit`; `Run` returns the exit code.

# FEATURE: Column Select

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Profile only the column named by --column and reject an absent column name with exit 3. |
| Depends On  | FEATURE-CliOptions.md, FEATURE-NullTrim.md, ARCHITECTURE.md |
| Provides    | --column behavior |
| Consumes    | --column, reader.Trim |

## Questions

- None.

## Purpose

`--column <name>` narrows the profile to a single column. The name is matched against the trimmed header names, exactly and case-sensitively. A name absent from the header is a rejected input.

## Behavior

- The `--column` value is compared to each trimmed header name by exact, case-sensitive string equality.
- A match produces the profile header plus one row for that column only, with statistics computed exactly as in the full profile.
- No match exits 3, writes nothing to standard output, and writes one diagnostic to standard error naming the file and the missing column.
- The check runs after the file has been read and validated, so a malformed file still exits 3 for its own reason.

# FEATURE: Usage Errors

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Reject invalid command lines with exit 2, nothing on standard output, and both synopses on standard error. |
| Depends On  | FEATURE-CliOptions.md, ARCHITECTURE.md |
| Provides    | exit 2 on usage errors |
| Consumes    | --column, --freq, --top |

## Questions

- None.

## Purpose

Any malformed command line exits 2 before the file is opened. Standard output stays empty, and standard error receives both synopses so the user can see the valid forms.

## Usage Errors

- No file argument, or more than one file argument.
- An unknown option, including `--help` and `-h` (no help flag is defined).
- An option that requires a value but has none.
- `--top` whose value is not a positive integer (zero, negative, or non-numeric).
- `--top` given without `--freq`.
- `--column` given together with `--freq`.

## Behavior

- Exit code is 2 for every case above.
- Standard output is empty.
- Standard error receives both synopses: `csvstat [--column <name>] <file>` and `csvstat --freq <name> [--top <n>] <file>`.
- Usage errors are decided before the file is opened, so a nonexistent file never turns a usage error into exit 1.
