# FEATURE: Null Values

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Recognise null spellings (empty, NA, N/A, NULL ignoring case) on trimmed values. |
| Depends On  | FEATURE-Trimming.md, FEATURE-CsvReading.md |
| Provides    | csvdata.IsNull |
| Consumes    | csvdata.Read |

## Questions

- None.

## Purpose

Statistics, type inference and frequency counting all need one shared definition of "null". This
feature provides it as a function in `internal/csvdata` so no other package re-implements it.

## Behavior

- `func IsNull(value string) bool` in package `csvdata` receives a value that has already been
  trimmed of leading and trailing spaces.
- A value is null when it is the empty string, or equals `NA`, `N/A`, or `NULL` ignoring case
  (`na`, `n/a`, `Null` and `null` are null).
- Every other value is non-null, including `0`, `false`, `NAN`, `N/B`, `NULLS` and `NA ` is not
  an input (trimming precedes this rule), so only exact spellings match.
- A quoted empty field (`""`) is read by `encoding/csv` as an empty string, so it is null.
- A field made only of spaces is empty after trimming and is therefore null.
- `IsNull` is pure: it never reads files and never allocates state.

acceptance can run them):

- `TestIsNullEmpty`

# FEATURE: Input Rejection

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Reject empty files, blank-only files, empty or repeated header names, and ragged records with exit 3. |
| Depends On  | FEATURE-Trimming.md, FEATURE-CsvReading.md, FEATURE-Arguments.md |
| Provides    | csvdata.ErrRejected |
| Consumes    | csvdata.Read, cli.ParseArgs |

## Questions

- None.

## Purpose

Malformed input must never produce partial output. Rejection is detected in `internal/csvdata`
and mapped to exit code 3 by `internal/cli`.

## Behavior

- `csvdata` exposes a rejection error type (sentinel or typed error matched with `errors.Is` /
  `errors.As`) named `ErrRejected`. For a ragged record it carries the 1-based line number.
- The file is rejected when:
  - it is empty (zero bytes);
  - it contains only blank lines;
  - any header name is empty after trimming;
  - any header name repeats (compared exactly after trimming);
  - any record has a different number of fields from the header.
- A header-only file is valid and yields zero data records.
- A trailing line ending after the last record creates no extra record.
- `cli.Run` reads the file named by the parsed arguments. On a rejection error it writes nothing
  to standard output, writes one diagnostic line to standard error naming the file (and the line
  number for a ragged record), and returns exit code 3.
- A CSV syntax error from `encoding/csv` (for example a bare quote) is also a rejection, exit 3.

# FEATURE: Numeric Types

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Infer integer and number column types from the non-null values of a column. |
| Depends On  | FEATURE-NullValues.md |
| Provides    | profile.InferType (integer, number) |
| Consumes    | csvdata.IsNull |

## Questions

- None.

## Purpose

Column typing decides which statistics apply. This feature starts `profile.InferType` in
`internal/profile` with the two numeric types. Later features extend the same function with
`date`, `boolean`, `text`, and `empty`.

## Behavior

- `func InferType(values []string) string` in package `profile` receives the trimmed values of one
  column and returns the type name.
- Null values (per `csvdata.IsNull`) are ignored.
- A column is `integer` when every non-null value matches `-?[0-9]+`.
- Otherwise it is `number` when every non-null value matches `-?[0-9]+(\.[0-9]+)?`.
- Integer is tested before number, so a column of whole numbers is `integer`; a single decimal
  value makes the column `number`.
- Matching is anchored over the whole value and uses no float parsing. Values such as `+1`, `1.`,
  `.5`, `1e3`, `1,5`, `0x10`, and `-` are not numeric.
- When a column has at least one non-null value that is not numeric, this feature returns the
  fallback `text` until later features add the remaining types.
- A column whose non-null values are all null returns `empty`.

# FEATURE: Date Type

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Infer date columns whose non-null values are real YYYY-MM-DD calendar dates. |
| Depends On  | FEATURE-NumericTypes.md |
| Provides    | profile.InferType (date) |
| Consumes    | csvdata.IsNull, profile.InferType |

## Questions

- None.

## Purpose

Extend `profile.InferType` so date columns are recognised and sort chronologically in later
statistics.

## Behavior

- After integer and number are ruled out, a column is `date` when every non-null value has the
  shape `YYYY-MM-DD` (four digits, hyphen, two digits, hyphen, two digits) and is a real calendar
  date.
- Real-date validation uses `time.Parse` with layout `2006-01-02` in addition to the digit-shape
  check, so `2025-02-30`, `2025-13-01`, and `2025-02-29` are not dates while `2024-02-29` is.
- Shapes such as `2025-2-3`, `2025/02/03`, `20250203`, and `2025-02-03T10:00` are not dates.
- Null values are ignored.
- One non-date value makes the column fall through to later types (`boolean`, then `text`).
  Integer and number take precedence, but no YYYY-MM-DD value can match them.

# FEATURE: Boolean and Text Types

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Infer boolean, text, and empty column types, completing the type order. |
| Depends On  | FEATURE-DateType.md |
| Provides    | profile.InferType (boolean, text, empty) |
| Consumes    | csvdata.IsNull, profile.InferType |

## Questions

- None.

## Purpose

Complete `profile.InferType` so every column receives exactly one type: the first of `integer`,
`number`, `date`, `boolean`, `text` that every non-null value satisfies, or `empty` when there is
no non-null value.

## Behavior

- A column is `boolean` when every non-null value equals `true` or `false` ignoring case
  (`True`, `TRUE`, `false`, `False`). Values such as `yes`, `1`, `0`, and `t` are not boolean.
- `text` is the fallback for any column that satisfies none of the earlier types.
- A column with no non-null value (every value null, or zero data rows) is `empty`.
- The order of evaluation is: empty check, integer, number, date, boolean, text.
- A column of `0` and `1` is `integer`, not boolean.
- Original value case is preserved for distinct counting; only classification ignores case. The
  min and max statistics later render booleans as lowercase `true` or `false` regardless of input
  case; that rendering belongs to the min/max feature.
- Null values are ignored during classification.
