The published shape of this foundation. It is built before every other foundation: a web server,

  cmd/                    # one directory per binary, each package main
  internal/               # application packages; not importable outside this module

Application foundations add packages under `internal/`. The generated persistence library is a

Initialize the root `go.mod` in the language foundation before the DATABASE block.

### How do we execute and measure Acceptance Criteria in this language?

An Acceptance Criterion (AC) is an executable check of Blueprint-required behavior. Native tests
use `testing` in `*_test.go`; the project gate is `go test ./...`. Within the existing Blueprint
Python AC container, execute a named test through the shipped helper:

```python
from drydock_go import run_test
result = run_test("./internal/orders", "TestCreateOrder")
assert result.passed, (result.status, result.stdout, result.stderr)
```

Drydock stages this helper beside the criterion. It runs `go test -json -count=1 -run` with an
exact test name, retains output and per-test outcomes, and rejects absent/skipped tests as proof.
The enclosing AC provides identity, timeout, result storage and repair state. Compilation errors
remain distinct from assertion failures in `result.status`. Coverage and persistence observations
require explicit instrumentation per criterion; unavailable observations are unknown.

A criterion that exercises the command line runs the built executable through the same helper,
never `go run`, which reports every non-zero program exit as 1:

```python
from drydock_go import cli_runner
code, out, err = cli_runner("--top", "0", "data.csv")
assert code == 2, (code, out, err)
```

`cli_runner` builds the single `./cmd/<name>` main package once with `go build` and returns
`(exit_code, stdout, stderr)`; pass `package="./cmd/<name>"` when there are several, and `input=`
for standard input. A failed build settles the criterion as `execution-error`.

- The first row is the header `column,type,rows,nulls,distinct,min,max,sum,mean,median` (ten fields).

  later stories (Type-*, Profile-Counts, Profile-Extremes, Profile-Numeric-Stats). Until a later
  story is built, the field is written empty. The final application fills all of them.

# FEATURE: Type Integer

## Purpose

Start the first-match type ladder in `internal/infer` and fill the `type` field of each profile row
for integer columns.

## Behavior

- A column is `integer` when it has at least one non-null value and every non-null value, after
  trimming, matches `-?[0-9]+`.
- Null values (empty, `NA`, `N/A`, `NULL` ignoring case) are ignored for inference.
- Leading zeros are allowed. A decimal point, a leading `+`, an exponent, or any other character
  makes the column not integer.
- Columns this story does not classify leave `type` empty until later type stories are built.
  Column with no non-null value is never `integer`.

## Interfaces

- `internal/infer` exposes a classification function over a column's non-null trimmed values; the
  profile writer calls it per column.

| Version     | 20261025 V1 |
| Description | Compute exact sum, mean, and median for integer and number columns using arbitrary-precision rational arithmetic. |
| Depends On  | FEATURE-Type-Text-Empty.md, FEATURE-Profile-Counts.md |

## Purpose

Fill the `sum`, `mean`, and `median` fields for columns typed `integer` or `number`. All arithmetic is exact (`math/big`, `big.Rat`); rounding happens once, when the value is written.

## Behavior

- Only non-null values participate. The count used for the mean is the non-null count.

- `internal/decimal` provides the formatter that rounds a `big.Rat` once, half away from zero, to two decimals. Its exact contract is owned by the decimal rounding story.

# FEATURE: Decimal Rounding

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Define the exact two-decimal formatting contract that rounds once from the exact value, half away from zero. |
| Depends On  | FEATURE-Profile-Numeric-Stats.md |
| Provides    | decimal formatting contract |
| Consumes    | internal/decimal |

## Purpose

Make `internal/decimal` exact and total. Every decimal the tool writes (number sum, every mean, every median, and later number min and max) goes through one formatter.

## Behavior

- Input is an exact `big.Rat`. The result is rounded once, half away from zero, to exactly two decimal places.
- A tie rounds away from zero: `0.005` becomes `0.01`, `-0.005` becomes `-0.01`, `2.675` becomes `2.68`, `1.005` becomes `1.01`.
- A leading `-` appears only when the rounded value is negative; a value that rounds to zero is written `0.00`, never `-0.00`.
- No thousands separator, no exponent, always two digits after the point, at any magnitude.
- Integer min, max, and sum remain plain integers and do not use this formatter.
- Number min and max use this formatter; they are verified by the extremes story, which is built after this one.

## Suite Pattern

The project's own `go test` suite exercises `internal/decimal` directly with table tests: ties in both signs, values just below and above a tie, zero, negative values that round to zero, and magnitudes beyond `float64`.

def fmt2(fr):
    scaled = fr * 100
    n, d = scaled.numerator, scaled.denominator
    r = (abs(n) * 2 + d) // (2 * d)
    sign = "-" if (n < 0 and r != 0) else ""
    return sign + str(r // 100) + "." + str(r % 100).zfill(2)

def real(values):
    return [Fraction(v) for v in values if v.lower() not in ("", "na", "n/a", "null")]

## Purpose

`csvstat --column <name> <file>` writes the profile header and exactly one row: the row of the
named column. That row is identical to the same column's row in the full profile. An unknown column
name is owned by FEATURE-CLI-Unknown-Column.md (exit 3), and combining `--column` with `--freq` is
owned by FEATURE-CLI-Option-Validation.md (exit 2).

## Behavior

- Output is the header `column,type,rows,nulls,distinct,min,max,sum,mean,median` followed by one
  row for the named column.
- The column is matched by exact trimmed header name.
- The row is computed by the same code path as the full profile, so `rows` still counts every data
  record and every statistic covers the whole column.
- A header-only file with `--column` yields the header and one row with `rows` 0.
