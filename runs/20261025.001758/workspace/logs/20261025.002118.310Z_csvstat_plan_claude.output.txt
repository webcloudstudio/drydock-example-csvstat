# FEATURE: CSV Reading

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Read a UTF-8 RFC 4180 CSV file with encoding/csv and trim every header name and value of leading and trailing spaces. |
| Depends On  | ARCHITECTURE.md, FEATURE-CLI-Arguments.md |
| Provides    | csvdata.Read |
| Consumes    | internal/cli.Run |

## Questions

- None.

## Purpose

`csvstat` profiles a CSV file. Every later rule (null detection, type inference, statistics,
frequencies) works on the trimmed table this feature produces, so trimming happens here, before
any other rule applies.

## Behavior

- `internal/csvdata` exposes `Read(path string) (Table, error)`.
- `Table` carries `Header []string` and `Records []Record`. `Record` carries `Line int` (the 1-based
  line on which the record starts, as reported by `csv.Reader.FieldPos`) and `Fields []string`.
- The file is read with `encoding/csv`. `FieldsPerRecord` is set to `-1` so that a record whose
  width differs from the header is returned to the caller intact; the rejection rules are owned by
  FEATURE-CSV-Rejection.md.
- The first record is the header. Every header name and every value has leading and trailing
  spaces trimmed (`strings.Trim(s, " ")`) before any other rule.
- Quoted fields decode per RFC 4180: a quoted field may contain commas, doubled quotes and newlines.
- `Read` returns an error that wraps the underlying `*os.PathError` when the file cannot be opened
  or read, so callers can tell an operational failure from a content problem.
- After argument validation, `cli.Run` reads the file with `csvdata.Read`. A successfully read file
  exits `0`; what is written to standard output is defined by later stories.

## Required unit tests

The build agent writes these tests in `internal/csvdata` with exactly these names:

- `TestReadTrimsHeaderAndValues`
- `TestReadQuotedFieldWithComma`
- `TestReadReturnsRaggedRecordsWithLineNumbers`

# FEATURE: Null Values

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Classify a trimmed value as null when it is empty or equals NA, N/A, or NULL ignoring case. |
| Depends On  | ARCHITECTURE.md, FEATURE-CSV-Reading.md |
| Provides    | csvdata.IsNull |
| Consumes    | csvdata.Read |

## Questions

- None.

## Purpose

Null handling is one rule shared by every statistic: nulls count toward `rows` and `nulls` but are
ignored by `distinct`, `min`, `max`, `sum`, `mean`, `median`, type inference and frequencies.

## Behavior

- `internal/csvdata` exposes `IsNull(value string) bool`, applied to already-trimmed values.
- It returns true for the empty string and for `NA`, `N/A` and `NULL` in any letter case.
- It returns false for every other value, including `0`, `nan`, `none`, `n/a/` and `NAN`.
- No other package re-implements the null rule; all call `csvdata.IsNull`.

## Required unit tests

The build agent writes these tests in `internal/csvdata` with exactly these names:

- `TestIsNullEmptyAndSentinels` covers the empty string and every case variant of `NA`, `N/A`, `NULL`.
- `TestIsNullRejectsLookalikes` covers `0`, `nan`, `none`, `NAN`, `nul` and `n/a/`.

=== BEGIN ARTIFACT FEATURE-CSV-Rejection.md ===
# FEATURE: CSV Rejection

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Reject an empty file, an empty or repeated header name, or a ragged record with exit 3, no standard output and one diagnostic line. |
| Depends On  | ARCHITECTURE.md, FEATURE-CSV-Reading.md |
| Provides    | rejected-input exit 3 |
| Consumes    | csvdata.Read |

## Questions

- None.

## Purpose

A malformed file is rejected as a whole. Nothing is profiled and nothing reaches standard output,
so a caller never mistakes partial output for a result.

## Behavior

- After reading, `cli.Run` validates the table and exits `3` with nothing on standard output when:
  - the file has no records at all (zero bytes, or only blank content);
  - a header name is empty after trimming (including a header of only spaces);
  - a header name appears more than once (exact string comparison after trimming);
  - any data record has a field count different from the header;
  - `encoding/csv` reports a syntax error (for example a bare quote); this is rejected content, so
    it is exit `3`, not `1`.
- Exactly one diagnostic line is written to standard error. It names the file and, for a ragged
  record, the record's line number (`Record.Line`).
- A header followed by no data records is valid and is not rejected.
- Exit `1` (unreadable file) is owned by FEATURE-Read-Failure.md; exit `2` by the CLI features.

## Required unit tests

The build agent writes this test in `internal/cli` with exactly this name:

- `TestRejectionDiagnosticNamesFileAndLine` runs `Run` with `bytes.Buffer` writers on a ragged file
  and asserts stdout is empty, stderr is a single line, and that line contains the file path and the
  line number of the ragged record.

# FEATURE: Read Failure

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Exit 1 with nothing on standard output when the file cannot be opened or read. |
| Depends On  | ARCHITECTURE.md, FEATURE-CSV-Rejection.md |
| Provides    | operational-failure exit 1 |
| Consumes    | csvdata.Read |

## Questions

- None.

## Purpose

An operational failure (the file is unavailable) is distinguished from rejected content so callers
can tell a missing input from a malformed one.

## Behavior

- When `csvdata.Read` fails to open or read the path (nonexistent path, a directory, no
  permission), `cli.Run` exits `1`.
- Nothing is written to standard output; one diagnostic line naming the file is written to standard
  error.
- Exit `1` is reserved for this case. Content that was read but rejected is exit `3`
  (FEATURE-CSV-Rejection.md); usage errors are exit `2` (FEATURE-CLI-Arguments.md and
  FEATURE-CLI-Option-Validation.md).

## Programmatic Acceptance

    assert code == 1
    assert out == ""
=== END AC read-failure-missing-file ===

=== AC read-failure-distinct-from-rejection ===
Intent: A readable but ragged file exits 3 while an unreadable one exits 1, so the two codes are not conflated.

import os
import tempfile
from drydock_go import cli_runner

ragged = os.path.abspath(os.path.join("sources", "ragged.csv"))
with tempfile.TemporaryDirectory() as d:
    missing = os.path.join(d, "absent.csv")
    rejected_code, _, _ = cli_runner(ragged)
    failed_code, out, err = cli_runner(missing)
    print(out)
    print(err)
    assert rejected_code == 3
    assert failed_code == 1
    assert failed_code != rejected_code

- None.

## Guardrails

- Exit `1` never accompanies output on standard output.
- Usage errors are not handled here and keep exit `2`.

# FEATURE: Profile Rows

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Emit the profile header and one row per column in file order, filling column and rows. |
| Depends On  | ARCHITECTURE.md, FEATURE-CSV-Reading.md, FEATURE-Null-Values.md, FEATURE-CSV-Rejection.md, FEATURE-CLI-Option-Validation.md |
| Provides    | profile output header |
| Consumes    | csvdata.Read, csvdata.IsNull |

## Questions

- None.

## Purpose

This is the skeleton of the profile output. Later stories fill the remaining fields, so the output
shape is fixed here and never changes.

## Behavior

- Without `--freq`, standard output is CSV written by one `encoding/csv` writer with `\n` line
  endings.
- The first row is the header `column,type,rows,nulls,distinct,min,max,sum,mean,median` (ten fields).
- One row follows for each header column, in file order. Every row has ten fields.
- `column` is the trimmed header name. `rows` is the number of data records (not counting the
  header), written as a plain integer; a header-only file gives `0` for every column.
- The fields `type`, `nulls`, `distinct`, `min`, `max`, `sum`, `mean` and `median` are owned by
  later stories (Type-*, Profile-Counts, Profile-Extremes, Profile-Numeric-Stats). Until a later
  story is built, the field is written empty. The final application fills all of them.
- Exit `0` on success.

## Programmatic Acceptance

=== AC profile-rows-header-and-columns-in-file-order ===
Intent: The profile starts with the ten-field header and lists one row per input column in file order.

import csv
import io
import os
from drydock_go import cli_runner

data = os.path.abspath(os.path.join("sources", "employees.csv"))
with open(data, newline="") as f:
    source = list(csv.reader(f))
names = source[0]
code, out, err = cli_runner(data)
print(out)
print(err)
assert code == 0
parsed = list(csv.reader(io.StringIO(out)))
assert parsed[0] == ["column", "type", "rows", "nulls", "distinct", "min", "max", "sum", "mean", "median"]
assert [row[0] for row in parsed[1:]] == names
assert all(len(row) == len(parsed[0]) for row in parsed)
=== END AC profile-rows-header-and-columns-in-file-order ===

import os
