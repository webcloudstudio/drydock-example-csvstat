# FEATURE: Type Text and Empty

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Complete the column type ladder with the text fallback and the empty type for columns without non-null values. |
| Depends On  | FEATURE-Type-Boolean.md, FEATURE-Null-Values.md |
| Provides    | type text, type empty |
| Consumes    | csvdata.IsNull |

## Questions

- None.

## Purpose

Finish the first-match type ladder `integer`, `number`, `date`, `boolean`, `text`, and add `empty`. After this story every column of every readable file has a type token in the `type` field of the profile row.

## Behavior

- A column with no non-null value has type `empty`. This includes a column whose values are all null (empty, `NA`, `N/A`, `NULL` in any case) and every column of a file with a header and no data records.
- Otherwise the column takes the first of `integer`, `number`, `date`, `boolean` that every non-null value satisfies; if none is satisfied the type is `text`.
- Nulls never decide the type; they are removed before the ladder runs.
- Values are trimmed before classification.
- A date-shaped value that is not a real calendar date (`2025-02-30`) does not satisfy `date`; with no other match the column is `text`.
- Forms such as `1.`, `1e3`, `yes`, and `no` satisfy no numeric or boolean rule and fall to `text`.

## Suite Pattern

The project's own `go test` suite covers the ladder directly in `internal/infer` (one test per type, null-only column, empty slice, mixed columns, order of precedence).

# FEATURE: Profile Counts

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Compute the null count and the exact distinct count of non-null values for every profiled column. |
| Depends On  | FEATURE-Profile-Rows.md, FEATURE-Null-Values.md |
| Provides    | profile nulls, distinct |
| Consumes    | csvdata.IsNull |

## Questions

- None.

## Purpose

Fill the `nulls` and `distinct` fields of each profile row. The `rows` field is already produced by the profile rows story.

## Behavior

- `nulls` is the number of values in the column that are null: empty, or `NA`, `N/A`, `NULL` in any letter case, after trimming.
- `distinct` is the number of different non-null values compared as exact strings after trimming. Case differences count as different values (`Abc` and `abc`), and so do `1`, `01`, and `1.0`.
- `0`, `none`, and `nan` are not null.
- A column with no non-null values has `distinct` 0; a header-only file reports `nulls` 0 and `distinct` 0 for every column.
- Both counts are written as plain integers.

## Programmatic Acceptance

# FEATURE: Profile Numeric Stats

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Compute exact sum, mean, and median for integer and number columns using arbitrary-precision rational arithmetic. |
| Depends On  | FEATURE-Type-Text-Empty.md, FEATURE-Profile-Counts.md |
| Provides    | profile sum, mean, median |
| Consumes    | infer types, internal/decimal |

## Questions

- None.

## Purpose

Fill the `sum`, `mean`, and `median` fields for columns typed `integer` or `number`. All arithmetic is exact (`math/big`, `big.Rat`); rounding happens once, when the value is written.

## Behavior

- Only non-null values participate. The count used for the mean is the non-null count.
- `sum`: integer columns write the integer total; number columns write the total with exactly two decimal places.
- `mean`: sum divided by the non-null count, written with two decimal places for both integer and number columns.
- `median`: the middle value of the numerically sorted non-null values, or the mean of the two middle values when the count is even; written with two decimal places for both types.
- Sorting is numeric, never lexical (`9` sorts before `10`).
- For every other type (`text`, `date`, `boolean`, `empty`) the three fields are empty.
- `internal/decimal` provides the formatter that rounds a `big.Rat` once, half away from zero, to two decimals. Its exact contract is owned by the decimal rounding story.

## Programmatic Acceptance

# FEATURE: Decimal Rounding

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Define the exact two-decimal formatting contract that rounds once from the exact value, half away from zero. |
| Depends On  | FEATURE-Profile-Numeric-Stats.md |
| Provides    | decimal formatting contract |
| Consumes    | internal/decimal |

## Questions

- None.

## Purpose

Make `internal/decimal` exact and total. Every decimal the tool writes (number sum, every mean, every median, and later number min and max) goes through one formatter.

## Behavior

- Input is an exact `big.Rat`. The result is rounded once, half away from zero, to exactly two decimal places.
- A tie rounds away from zero: `0.005` becomes `0.01`, `-0.005` becomes `-0.01`, `2.675` becomes `2.68`, `1.005` becomes `1.01`.
- A leading `-` appears only when the rounded value is negative; a value that rounds to zero is written `0.00`, never `-0.00`.
- No thousands separator, no exponent, always two digits after the point, at any magnitude.
- Integer min, max, and sum remain plain integers and do not use this formatter.
- Number min and max use this formatter; they are verified by the extremes story, which is built after this one.

## Suite Pattern

The project's own `go test` suite exercises `internal/decimal` directly with table tests: ties in both signs, values just below and above a tie, zero, negative values that round to zero, and magnitudes beyond `float64`.

# FEATURE: Profile Extremes

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Compute the min and max of every column according to its inferred type. |
| Depends On  | FEATURE-Decimal-Rounding.md, FEATURE-Profile-Counts.md |
| Provides    | profile min, max |
| Consumes    | infer types, internal/decimal |

## Questions

- None.

## Purpose

Fill the `min` and `max` fields of each profile row. Null values are ignored throughout.

## Behavior

- `integer`: smallest and largest compared numerically, written as plain integers.
- `number`: smallest and largest compared exactly (`big.Rat`), written with the two-decimal formatter (`10.125` is written `10.13`).
- `date`: earliest and latest.
- `boolean`: `min` is `false` if any value is false (any letter case), else `true`; `max` is `true` if any value is true, else `false`. Output is lower case.
- `text`: smallest and largest by byte value of the trimmed string (`B` sorts before `a`; `10` sorts before `9`).
- `empty`: both fields are empty.
- A value that needs quoting (a comma, quote, or newline) is quoted by the shared CSV writer.
