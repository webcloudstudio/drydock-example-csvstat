<requirement name="build-go-cli" stories="cli-foundation">
Implement in Go 1.22 or newer using only the standard library. The application root is a Go module, and its executable is the main package at `./cmd/csvstat`. Tests run under `go test`.
</requirement>
<requirement name="run-conformance-harness" stories="full-verification">
The harness runs `go build -o <temporary path> ./cmd/csvstat` and then runs 22 checks.
</requirement>
<requirement name="read-validate-csv" stories="cli-input">
The file is **rejected** when it is empty, when a header name is empty or repeated, or when any record has a different number of fields from the header.
</requirement>
<requirement name="resolve-columns-null-values" stories="cli-columns">
Every header name and every value is trimmed of leading and trailing spaces before any other rule applies.
</requirement>
<requirement name="infer-column-types" stories="profile-types">
A column's type is the first of these that every non-null value satisfies:
</requirement>
<requirement name="compute-profile-statistics" stories="profile-statistics">
Header `column,type,rows,nulls,distinct,min,max,sum,mean,median`, then one row per column in file order (or the one named by `--column`).
</requirement>
<requirement name="render-profile-csv" stories="profile-output">
CSV on standard output with `\n` line endings.
</requirement>
<requirement name="list-frequent-values" stories="frequency-values">
Header `value,count`, then one row per distinct non-null value of the column, ordered by count descending, then value ascending by byte value, at most `--top` rows.
</requirement>
<requirement name="limit-frequency-rows" stories="frequency-limits">
`--top <n>` | With `--freq`, list at most `<n>` values. A positive integer; default `5`.
</requirement>
<requirement name="map-command-failures" stories="cli-errors">
A failing command writes nothing to standard output and one diagnostic line to standard error naming the file and, for a rejected record, its line number.
</requirement>
<requirement name="provide-test-gate" stories="test-gate">
The completed application provides a POSIX-compatible `bin/test.sh` that runs `go vet ./...` and `go test ./...` from the application root and exits zero only when both pass.
</requirement>
