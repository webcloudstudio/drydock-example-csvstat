# FEATURE: Frequency Limits

| Field       | Value |
|-------------|-------|
| Version     | 20261023 V1 |
| Description | Validate frequency limits and render bounded frequency output. |
| Depends On  | FEATURE-FREQUENCY-VALUES.md |
| Provides    | --top validation, default frequency limit, frequency CSV output |
| Consumes    | frequency aggregation and deterministic ordering |

## Questions

- None.

## Purpose

The frequency command accepts `--freq <name> [--top <n>] <file>`. The default limit is five. `--top` must be a positive integer and is valid only with `--freq`. The limit is applied after frequency ordering.

## Behavior

- Emit the CSV header `value,count`.
- Emit no more than the requested number of frequency rows.
- Reject zero, negative, or non-integer `--top` values with usage exit status 2.
- Reject `--top` without `--freq` with usage exit status 2.
- Preserve RFC-compliant CSV rendering.

## Programmatic Acceptance

=== AC frequency-limit-success ===
Intent: A valid positive limit executes the frequency command successfully and bounds the parsed result.
import csv
import io
import subprocess

column = "department"
limit = "2"
result = subprocess.run(
    ["./csvstat", "--freq", column, "--top", limit, "sources/employees.csv"],
    capture_output=True,
    text=True,
)
assert result.returncode == 0
rows = list(csv.reader(io.StringIO(result.stdout)))
assert rows[0] == ["value", "count"]
assert len(rows) <= int(limit) + 1
=== END AC frequency-limit-success ===

=== AC frequency-limit-default ===
Intent: Omitting --top uses the default limit and returns a successful frequency result.
import csv
import io
import subprocess

result = subprocess.run(
    ["./csvstat", "--freq", "department", "sources/employees.csv"],
    capture_output=True,
    text=True,
)
assert result.returncode == 0
rows = list(csv.reader(io.StringIO(result.stdout)))
assert rows[0] == ["value", "count"]
assert len(rows) <= 6
=== END AC frequency-limit-default ===

=== AC frequency-limit-invalid ===
Intent: Non-positive and malformed limits are rejected as usage errors.
import subprocess

cases = [
    ["--freq", "department", "--top", "0", "sources/employees.csv"],
    ["--freq", "department", "--top", "-1", "sources/employees.csv"],
    ["--freq", "department", "--top", "x", "sources/employees.csv"],
]
for args in cases:
    result = subprocess.run(["./csvstat", *args], capture_output=True, text=True)
    assert result.returncode == 2
    assert result.stdout == ""
=== END AC frequency-limit-invalid ===

=== AC top-requires-frequency ===
Intent: --top without --freq is rejected as a usage error.
import subprocess

result = subprocess.run(
    ["./csvstat", "--top", "3", "sources/employees.csv"],
    capture_output=True,
    text=True,
)
assert result.returncode == 2
assert result.stdout == ""
=== END AC top-requires-frequency ===

## User Acceptance

- None.

## Guardrails

- Do not include null values in frequency output.
- Do not change the ordering supplied by frequency aggregation when applying the limit.
- Do not read or embed expected answers from supplied grading assets.

# FEATURE: CLI Errors

| Field       | Value |
|-------------|-------|
| Version     | 20261023 V1 |
| Description | Map operational, usage, and rejected-input failures to the command contract. |
| Depends On  | FEATURE-CLI-COLUMNS.md, FEATURE-PROFILE-OUTPUT.md, FEATURE-FREQUENCY-LIMITS.md |
| Provides    | exit-code and diagnostic contract |
| Consumes    | CSV validation, column lookup, profile output, frequency output |

## Questions

- None.

## Purpose

The command reports failures through exit status and diagnostics. It must never write profile or frequency CSV to standard output after a failure.

## Error Contract

- Exit 1 for a file that cannot be opened or read.
- Exit 2 for missing or extra files, unknown options, missing option values, invalid `--top`, `--top` without `--freq`, or incompatible options.
- Exit 3 for empty input, invalid or repeated headers, ragged records, or absent named columns.
- Write one diagnostic line to standard error for failures.
- Diagnostics identify the input file and identify the rejected record line when a record is structurally invalid.

## Programmatic Acceptance

=== AC operational-error ===
Intent: An unreadable input file returns the operational failure status and no CSV output.
import pathlib
import subprocess

missing = "sources/does-not-exist.csv"
result = subprocess.run(["./csvstat", missing], capture_output=True, text=True)
assert result.returncode == 1
assert result.stdout == ""
assert pathlib.Path(missing).name in result.stderr
=== END AC operational-error ===

=== AC usage-errors ===
Intent: Malformed command arguments return usage status and no CSV output.
import subprocess

cases = [
    ["./csvstat"],
    ["./csvstat", "sources/orders.csv", "sources/employees.csv"],
    ["./csvstat", "--unknown", "sources/orders.csv"],
    ["./csvstat", "--column"],
]
for command in cases:
    result = subprocess.run(command, capture_output=True, text=True)
    assert result.returncode == 2
    assert result.stdout == ""
=== END AC usage-errors ===

=== AC rejected-input ===
Intent: Structurally invalid input and absent columns return rejected-input status and no CSV output.
import subprocess

cases = [
    ["./csvstat", "sources/ragged.csv"],
    ["./csvstat", "--column", "missing", "sources/orders.csv"],
    ["./csvstat", "--freq", "missing", "sources/orders.csv"],
]
for command in cases:
    result = subprocess.run(command, capture_output=True, text=True)
    assert result.returncode == 3
    assert result.stdout == ""
    assert result.stderr.strip()
=== END AC rejected-input ===

=== AC successful-output-isolated ===
Intent: A valid command remains successful and emits CSV on standard output.
import subprocess

result = subprocess.run(
    ["./csvstat", "--column", "qty", "sources/orders.csv"],
    capture_output=True,
    text=True,
)
assert result.returncode == 0
assert result.stdout != ""
=== END AC successful-output-isolated ===

## User Acceptance

- None.

## Guardrails

- Never emit partial CSV output before input validation and command execution succeed.
- Keep diagnostics on standard error.
- Preserve the distinct exit statuses for operational, usage, and rejected-input failures.
